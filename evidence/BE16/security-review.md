## Исправленные находки

1. **Высокая: HEAD мог утвердить план без CSRF.** В web.py:360–372 обработчик
   GET/POST отличал только GET, а автоматически разрешённый HEAD попадал в
   confirm. Авторизация врача оставалась, но HEAD с телом точного подтверждения
   обходил код защиты формы. Baseline-reproduction.json: HTTP200, care_actions
   0→1 без X-CSRF-Token в временной базе. Теперь GET/HEAD — только receipt.
   test_head_with_confirmation_body_never_mutates_or_bypasses_csrf и настоящий
   HTTP23 проверяют200/пустое тело/0записей. Исправлен такой же выбор ветки
   у прежнего self-report-draft (web.py:977): HEAD только читает черновик.
   Это не анонимное утверждение: необходима сессия уполномоченного врача и
   точные поля. SameSite/предсказуемость ID не заменяют корректный метод/CSRF.

2. **Средняя: сверка прежней врачебной связи раскрывалась новой.**
   backend_therapy_context.py:view/prepare возвращали последнюю пациентскую
   строку с fresh=false без ограничения relationship_id. Она попадала в API и
   затем в plan snapshot/history. Baseline-reproduction.json подтверждает
   выдачу canary новой связи. Теперь view:57 скрывает current, prepare:94–102
   возвращает None до копирования строки. Тест проверяет нового врача и
   повторную связь того же врача, API/входной снимок, сохранность исторической
   строки и возможность новой явной сверки. Общий монотонный номер версии
   сохранён для контроля конфликтов; старое содержимое/автор/ID не возвращаются.
   Обычная разрешённая история пациента сохраняется; это служебная сверка
   точной прежней связи, а не удаление медицинской истории.

3. **Усиление: конечные коды ошибок рискового компонента.**
   backend_risk_context.py:201–211 прежде переносил str(exc) из ModelError/
   ContextError/ExtractionError в сохраняемый отчёт. Произвольный код внутреннего
   адаптера мог содержать текст. Теперь только конечный разрешённый список,
   иначе model_input_or_response_invalid. Canary-тест проверяет API/log/worker/
   model report. Внешняя утечка реальных данных не наблюдалась и не утверждается.

4. **Минимизация данных.** backend_therapy.py:255–263 больше не передаёт
   physician_diagnosis_review_id поставщику; условие диагноза и кодированные
   необходимые сведения сохранены. Привязка к точному решению остаётся на
   сервере. Проверка payload исключает отдельные поля ID пациента/автора/связи,
   токены/пароли; произвольный медицинский текст потенциально содержит имена,
   поэтому это не обещание автоматического обезличивания и не допуск real data.

## Враждебные инструкции и модель

SYSTEM compass-model-v1: отдельный system и user, данные объявлены недоверенными,
нет tools/functions; tool_calls/refusal/неполный JSON отклоняются. Вход и ответ
ограничены байтами/токенами/сроком/деньгами; ключ только в транспортном заголовке.
Отбор текста и кодированных фактов узкий. Источники/формы/версии/права/сроки
сверяются сервером; подмена PDF/cards/revocation/unknown проверена sources tests.

Тесты помещают команду approve/role/999mg в дневник, подменяют поле роли,
выходной schema, unit/source/quote/snapshot/revision; запрет схемы/цитат и
врачебное утверждение сохраняются. Команда, процитированная точно, может остаться
**непроверенным кандидатом**, поэтому цитатная точность не названа защитой от
всех ложных клинических интерпретаций. Модель не меняет БД/назначение/канал;
правила риска независимы, неизвестное не превращается в «безопасно».

Настоящая модель проверена 7 новыми синтетическими вызовами:19случаев
(6положительных/13отказов без вызова),24постгенерационные подмены; отдельно
HTTP/defaultworker/перезапуск. Это авторский узкий набор и механические
диагностические фикстуры, не независимые клинические эталоны и не гарантия от
всех prompt injection. Финальные измерения — verification.json.

Первый старый протокол мутации менял только первый кандидат; модель вернула
ещё одну допустимую альтернативу, поэтому условие «нет рекомендаций» не прошло.
Новые вызовы не повторяли: verify_therapy.py независимо перепроверил сохранённые
настоящие ответы и изменил **каждый** кандидат в24проверках. Первичный лог
therapy-live.log сохранён; качество на неправильной пробе не объявлялось PASS.
Текущий gate evidence/BE14/therapy-quality.json обновлён только после проверки
точного нового runtime; прежний gate сохранён prior-therapy-quality.json.
