# Сравнение одинаковых задач S17E

Самопроверка автоматизированным браузером, синтетическая временная БД; реальных врачей/пациентов нет. Исходное приложение зафиксировано до изменения шаблонов; baseline.json содержит commit и SHA. Реальные снимки и JSON: before-after/before-result.json, after-result.json; дополнительный браузер — before-after/chrome/after-result.json. Время — фактический wall-clock performance.now() автоматического сценария, не время человека/терапевта и не измерение медицинской эффективности.

Одинаковые задания и данные:

1. Врач из карточки начинает первый приём, выбирает наличие жалоб, вводит одинаковые жалобу/основание и проект действия, сохраняет черновик. После используется ссылка шага4, до — длинная форма. Диагноз не вводится. Измерение включает снимок начальной формы в обеих фазах.
2. Пациент из карточки открывает самоотчёт, возвращается в обзор, открывает подтверждённые решения, возвращается и переходит к сообщениям. После ссылка называется «Подтверждённый план», до — «Решения врача». Отправка/чтение сообщений проверяются отдельно вне замера, условия одинаковы.

Действие здесь — один клик, заполнение одного поля целой строкой, выбор значения или один wheel на600CSSpx. Навигация/загрузка ожидаются. Автоматическая подсветка/фокус/перемещение браузера не объявляются действиями человека. Это определение нашего стенда, не требование/порог конкурса. Скрипт прокручивает, пока нужный элемент не находится в рабочей части окна. Перед повтором создаётся новая БД.

В основном пути врача уменьшилась прокрутка. Переключение шага добавило один клик; общее число действий стенда уменьшилось. У пациента число действий не изменилось: уточнились названия/расположение, улучшение скорости работы человека не доказано. Времена одного прогона не статистика, различия миллисекунд между браузерами не сравниваются как улучшение интерфейса.

Среда: macOS arm64, локальный Waitress/Python из .venv, Playwright из уже установленного рабочего runtime; Chromium151.0.7922.34, Google Chrome155.0.8059.82 (оба семейства Chromium). 1440×1000 для сравнения,320/768/1024/1440CSSpx для адаптации; CSS zoom200% эмулирует увеличение, не выдаётся за пользовательскую настройку браузера. Нет физического мобильного устройства, Safari/Firefox, screen reader, axe, участников или полной сертификации WCAG. Новые пакеты не устанавливались.

Замечания: исходный длинный путь требует13шагов прокрутки; шаг2 остаётся содержательным сбором сведений, его не сокращали до неподтверждённого опросника. Для сохранения после закрытия вкладки нужна кнопка черновика; при уходе с изменениями проверено стандартное предупреждение браузера. Короткий инструмент остаётся недоступным. DASS42 не изменена.

В ходе подготовки стенда исправлены гонка ожидания hash-перехода, ожидаемая точная подпись «Противоречивые сведения», селектор вида решения и путь импорта Python-фикстуры. Это дефекты стенда, не скрытые клинические результаты. Итоговые JSON/логи относятся к успешной версии сценария.
