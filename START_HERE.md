## Начало

```bash
git status --short
git log -5 --oneline
python3 tools/validate_plan.py
python3 tools/session.py status
python3 tools/session.py start S01
```

Последняя команда — пример первого среза; подставляйте фактически выбранный ID. Она не выполняет срез и не меняет accepted: только фиксирует in_progress и создаёт черновик отчёта. При открытом in_progress сначала восстановить/закончить его. Чужие изменения не удалять и не включать в свой коммит без понимания.

Проверить доступные изменения чата/email/официальных правил, состав команды, ближайшие внешние сроки, права компонентов и бюджет. Если доступа нет, записать ограничение; не просить повторно уже принятые предпочтения. Организаторам и другим людям не писать без явного поручения. Новые ответы могут менять план — сохранять источник и историю изменений.

## Завершение одной сессии

1. Выполнить условия приёмки карточки, проверить изменения напрямую, запустить реальные проверки, сохранить доказательства в evidence/SXX/.
2. Заполнить memory/sessions/SXX.md: фактические действия, проверки, все критерии, решения, блокеры и следующий шаг.
3. Обновить plan/coverage.json **реальными** доказательствами; не менять not_verified на fulfilled только из-за готового плана. Обновить STATE/решения/блокеры/ответы/бюджет.
4. Для принятого среза STATE: status=accepted, commit_ref=refs/tags/slice/SXX, current_slice=null, last_accepted_slice=SXX, next_slice=следующий готовый по зависимостям. Для блокера — blocked, причина и условие снятия, без тега приёмки. После изменения coverage.json выполнить `python3 tools/render_coverage.py`, чтобы читаемая матрица не отстала.
5. До коммита проверить план, разрешив только ещё не созданный тег этого среза:

```bash
python3 tools/validate_plan.py --pending-tag SXX
git diff --check
git diff
git add -- <точные файлы этого среза>
git commit -m 'slice(SXX): конкретный результат'
git tag slice/SXX
python3 tools/validate_plan.py
git status --short
```

SXX и список файлов заменить реальными значениями. Хеш собственного коммита нельзя записать внутрь него самого: память хранит стабильный тег, который создаётся **после** коммита. Проверка после тега обязательна. Существующий тег не переносить силой; исправления новым коммитом и новым документированным тегом, например slice/SXX-r2.

Допустимы промежуточные коммиты в одном срезе, но только проверенная конечная версия получает тег приёмки. Не делать amend/reset/force и не терять чужую работу. Публичного remote по умолчанию нет. Блокированная/незавершённая работа может получить честный WIP-коммит без тега принятия.

## Один срез — одна сессия

Не начинать соседний срез после завершения выбранного. Если объём не помещается, до расширения разбить оставшуюся работу на дочерние срезы с отдельными карточками, зависимостями и памятью; сохранить покрытие всех требований. Внешние ожидания не закрывать предположением. Можно выбрать независимый готовый срез в следующей сессии, оставив блокер явным.
