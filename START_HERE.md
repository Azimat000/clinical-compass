## Порядок работы

Одна сессия — один срез. До изменений проверить Git status/diff, зависимости,
доступные новые сведения, права/конфиденциальность и бюджет. Прежние незакоммиченные
файлы аудита не удалять и не включать без понимания. Новые внешние факты — только
read-only web-researcher с изолированным самодостаточным заданием. Делегированные
мутации — implementation-worker по полному протоколу AGENTS.md и точным путям.

```
git status --short
python3 tools/validate_plan.py
python3 tools/session.py status
```

В конце: прямой просмотр результата, реальные проверки, краткий отчёт и только
необходимые доказательства, обновление STATE/матрицы/решений/блокеров/бюджета.
Не плодить новые подготовительные срезы и большие дубли документов без реальной
необходимости. Неполное не принимать, соседний срез начинать в новой сессии.
После изменения coverage.json выполнить tools/render_coverage.py.

Для принятого среза записать stable ref refs/tags/slice/SXX, затем:

```
python3 tools/validate_plan.py --pending-tag SXX
git diff --check
git diff
git add -- <точные файлы>
git commit -m 'slice(SXX): конкретный результат'
git tag slice/SXX
python3 tools/validate_plan.py
git status --short
```

SXX заменить фактическим ID. Тег создавать после коммита, не перемещать существующий;
никаких amend/reset/force. Заблокированное — честный WIP без тега приёмки.
Планировочный тег не доказывает реализацию, клиническую безопасность или победу.
Публикации, покупки, сообщения людям и реальные медицинские действия не следуют
из поручения разработать сервис. Бюджет ≤5000₽, расходы/обязательства пока0₽.
