# Передача работы между сессиями BE01–BE19

## Источники правды

- `memory/STATE.json`: текущий/последний/следующий срез, статус каждого, отчёт и стабильный Git-тег. Планировочное изменение не меняет последний принятый S56 на фиктивный BE.
- `plan/manifest.json` и `plan/slices/BE*.md`: зависимости, работа, артефакты, условия приёмки и команды проверок.
- `plan/backend/requirements.json`: все требования нового поручения и их фактические доказательства. `plan/coverage.json`: исходные требования, сохраняемые вместе с этим планом.
- `memory/sessions/BE##.md` и `evidence/BE##/acceptance.md`: фактический результат, проверка каждого критерия и передача следующей сессии. Использовать `memory/SESSION_TEMPLATE.md`.
- `memory/DECISIONS.md`, `BLOCKERS.md`, `EXTERNAL.md`, `BUDGET.json`: решения, открытые препятствия, источниковые ограничения, реальные расходы. Отчёт не зависит от памяти чата.

## Начало одной сессии

1. Прочитать START_HERE/AGENTS/STATE и четыре файла памяти выше, последний принятый отчёт/приёмку, карточку выбранного среза, этот протокол и отчёты его зависимостей.
2. Зафиксировать `git rev-parse HEAD`, `git status --short`, staged/unstaged diff. Не сбрасывать/включать чужие изменения. Если Git/файлы недоступны, сохранить точное описание и доступный baseline; не объявлять чистоту/коммит без проверки.
3. Проверить применимые зависимости, доступные новые источники/ответы, права и бюджет. Не возвращать отложенную организационную работу. Внешние факты — через изолированного web-researcher.
4. Выполнить `python3 tools/validate_plan.py` и `python3 tools/session.py status`. Если зависимости приняты, `python3 tools/session.py start BE##`. Одновременно один in_progress.
5. Записать точные writable-пути/миграции и критерии. При делегировании использовать только implementation-worker, полный пакет/ledger из AGENTS.md и непересекающуюся собственность. Незнакомый номер миграции не резервировать заранее.

## Во время работы

Изменения приложения проверять в отдельной копии синтетической базы. Рабочую базу/учётные записи/исторические строки не пересоздавать. Сохранение сырых данных и подтверждение врача остаются серверными. Измерения модели, стоимость, версии и ошибки фиксировать фактически. Клинические тесты без независимого подтверждения маркировать синтетическими; не заполнять фиктивный reviewed_by.

Если критерий не помещается в сессию, сначала выделить дочерний срез: обновить manifest, карточки, STATE и обе матрицы; перенести каждый исходный критерий явно. Нельзя принять исходный срез как полный, оставив его критерий «на потом». Если нужен внешний ответ, записать блокер и условия снятия; зависимые срезы не начинать. Соседний независимый срез — только новая сессия.

## Завершение и коммит

1. Дождаться всех изменяющих агентов. Сверить их полный handoff, реальные файлы/diff и baseline. Основной агент сам запускает целевые проверки и общую регрессию. После интеграции повторять только нужные проверки.
2. Заполнить `evidence/BE##/acceptance.md`: каждый BE##-Axx → код/вывод/файл/измерение → PASS/FAIL. Добавить результаты требований B01–B16 и применимых F/M/E/T/C. Недоказанное не повышать.
3. Обновить `memory/sessions/BE##.md`, STATE, DECISIONS/BLOCKERS/EXTERNAL/BUDGET, матрицы и краткий текущий шаг START_HERE. При изменении исходной матрицы: `python3 tools/render_coverage.py`.
4. В отчёте обязательно оставить точные версии модели/инструкций/источников; изменения/миграции и способ восстановления; команды и результаты; открытые ошибки; границы клинического допуска; сохранённые чужие файлы; расходы; следующий готовый срез и первую команду. Не сохранять секреты/реальные медицинские тексты в Git.
5. При полной приёмке установить accepted, current_slice=null, last_accepted_slice=BE##, commit_ref=`refs/tags/slice/BE##`, next_slice по зависимостям. Затем:

```sh
python3 tools/validate_plan.py --pending-tag BE##
git diff --check
git diff
git diff --cached
git add -- <только проверенные файлы среза>
git commit -m 'slice(BE##): конкретный результат'
git tag slice/BE##
python3 tools/validate_plan.py
python3 tools/session.py status
git status --short
```

6. При blocked/in_progress — честный отчёт и WIP-коммит с причиной, без тега приёмки и без принятия зависимых срезов. Существующие теги не перемещать, amend/reset/force не применять.
7. Сообщить пользователю результат этого среза, реальные проверки, ограничения, коммит/тег и следующий шаг. Остановиться; следующий срез в этом чате в той же сессии не начинать.

`BE##` — подстановка фактического ID, не буквальная команда. Покупка, внешний медицинский канал, публикация, сообщения людям и реальный медицинский запуск не следуют из разрешения на локальную разработку. При недоступном Git сохранить файлы/отчёт, но явно оставить коммит и тег невыполненными; не создавать новую историю вместо старой.
