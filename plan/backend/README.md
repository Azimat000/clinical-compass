## Результат продукта

Ровно три клинических результата, доступные врачу:

1. Выявлять потенциально опасные паттерны из анкет, дневника самочувствия, анамнеза и записей приёма; сообщать только уполномоченному врачу.
2. Предлагать ведущую диагностическую гипотезу и существенные альтернативы по тем же данным, показывая основания, противоречия и недостающие сведения.
3. Предлагать содержательный план и лечение по тем же данным и диагнозу; применять только после отдельного решения врача.

Сбор данных, источники, модель, очередь, API, аудит и проверки — внутренняя основа этих трёх функций. Не добавляются чат-бот, медицинская поисковая система для пользователя, автономное назначение или самостоятельное четвёртое направление. Существующие формы и функции сервиса сохраняются; поручение не означает удаление накопленных данных и прежних требований.

## Границы текущего плана

Только сервер, данные, модель, фоновые задачи, API и проверки. HTML/CSS/JS, композиция экранов, анимации, возврат удалённых уведомлений/врачебных форм и новые интерфейсные срезы здесь не планируются. UI08 остаётся отдельной незавершённой работой; дальнейший интерфейс — отдельный план. «Красиво и классно» на backend означает понятный и стабильный ответ, короткое объяснение с проверяемыми деталями, предсказуемые состояния, отсутствие дублей и устаревших результатов, быстрый независимый путь риска и честное поведение при сбоях. Визуальное качество ещё не реализовано.

Назначение проекта и исходные F01–F08/M01–M10/E01–E06/T01–T13/C01–C46 сохраняются. Первая версия не объявляется универсальной для всех болезней и возрастов: BE01 закрепляет матрицу конкретной поддерживаемой области, BE03/07/10/12/13/14 заполняют её проверяемыми источниками/правилами. Неподдерживаемое возвращает явный результат. Нельзя сузить область молча или выдать одни отказы за выполнение трёх функций.

Новых моделей/API/платежей/реальных медицинских действий этой планировочной сессией не подключается. Бюджет всего проекта ≤5000 ₽; новые обязательства не создаются. ## Устройство и переиспользование

Общая схема: четыре вида записей → неизменяемый снимок фактов → независимая оценка рисков / запрос гипотез / запрос плана → врачебные решения. План использует точную версию диагноза; новый существенный факт делает незавершённый проект устаревшим. Диагноз и лечение подтверждаются раздельно. Сигнал риска не ждёт готовности диагноза или плана.

- Существующие snapshots/врачебные связи/источниковые выпуски/clinical_rules/critical/outbox/worker/decisions/care_actions/medications используются после проверки фактического кода. План не предписывает второй параллельный механизм.
- Один адаптер языковой модели; три продуктовые операции. Многоагентная продуктовая архитектура не обязательна. Модель извлекает/предлагает; сервер проверяет структуру, ссылки, допустимость и права. У модели нет инструмента самостоятельно назначить лечение.
- Клиническое утверждение связано с конкретным первоисточником и версией. Справочная память модели не источник. Полный RAG/старые девять досье остаются отложенными; небольшое получение нужных оснований допустимо без возвращения всей программы.
- Для лекарств отдельный проверяющий механизм. Неизвестные аллергии/взаимодействия/обязательные сведения не превращаются в «ограничений нет». Внеинструкционные предложения автоматически не активируются.
- Сохранённая запись не зависит от успешного ответа модели. Повтор запроса не дублирует событие/план. Сбой/неполнота/неприменимость видны как отдельные состояния.
- Изоляция и клинические ограничения входят во все срезы с самого начала; BE16 — дополнительная сквозная проверка, не отсрочка защит.

## Проверка результата

Новая матрица поручения — [requirements.json](requirements.json), 16 пунктов B01–B16; это локальные идентификаторы требований, не номера блокеров memory/BLOCKERS.md. Исходная конкурсная матрица — ../coverage.json; в ней добавлены только связи с будущими проверками, ни один статус выполнения не повышен.

Для каждой функции нужны содержательные положительные случаи и случаи корректного отказа. Метрики задаются до итогового прогона и измеряются отдельно: факты/отрицания/время; пропущенные риски и ложные тревоги; обоснованность гипотез и важных альтернатив; неподходящие варианты лечения и корректные назначения в поддерживаемой области; доставка/повторы/ошибки/задержки. Качество на закрытом наборе не подменяется успешными тестами структуры JSON. Модель, инструкции, источники, данные и оборудование фиксируются в отчёте.

BE18 — готовый технический backend на разрешённых синтетических данных с настоящей моделью и серверной интеграцией. BE19 — отдельный клинический барьер: реальное независимое заключение, применимость к точной версии и обязательные основания. Отсутствующий эксперт оставляет BE19 blocked; собственная синтетика, другой ИИ и Git-тег не заменяют его. Ни один из этих срезов сам по себе не даёт права на реальную апробацию или закрывает отложенную организационную работу.
