# S03. Синтетические случаи и независимый набор проверки

Целевой период: 19–20.10. Одна сессия. Условие: always.

Зависимости: S02.

## Контекст начала

Прочитать AGENTS.md, START_HERE.md, memory/STATE.json, memory/DECISIONS.md, memory/BLOCKERS.md, memory/EXTERNAL.md, memory/BUDGET.json и отчёт последнего принятого среза. Проверить git status, доступные обновления условий и подпункты закреплённых требований. Не считать прошлую переписку единственной памятью.

## Что делаем

1. Подготовить шесть основных случаев: подходящее рассмотрение Авиандра, ограничения, депрессивная симптоматика, критическое ухудшение, НЯ/пропуски, неполнота/противоречия.

2. Каждый основной случай содержит профиль, рассмотрение препарата, рекомендации и маршрутизацию.

3. Создать 30–60 историй разных шаблонов как рабочую цель; разметить факты и критичные пропуски; разделить по профилям, не по перефразировкам.

4. Отдельно пометить непроверенные врачом эталоны; не использовать ответ модели как единственный клинический эталон.

## Условия приёмки

- [ ] Нет реальных ПД; у случаев есть происхождение и маркировка синтетических.

- [ ] Контрольные профили не встречаются в разработочной части; разные шаблоны включают отрицания/единицы/даты/назначения.

- [ ] Медицински непроверенные ожидания не объявлены клинически валидированными.

## Завершение

Создать memory/sessions/S03.md по memory/SESSION_TEMPLATE.md; обновить STATE, решения, блокеры, внешние ответы, бюджет и фактическую матрицу. Коммит: `slice(S03): <конкретный результат>`. После принятого коммита создать тег `slice/S03`. В STATE хранится тег, а не собственный хеш ещё не созданного коммита. Следующий срез начинается в новой сессии.

При внешнем блокере оставить статус blocked с доказательством/условием снятия и передать независимую работу; при превышении объёма сначала разбить срез с сохранением всех требований. Не переходить к соседнему срезу внутри этой сессии.
