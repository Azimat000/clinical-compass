# S26A. Интерфейс «Бланк»: основа и применение ко всем экранам

STATUS: PLANNED. Основание: прямое поручение пользователя 21.10.2026 переделать интерфейс сервиса с нуля в выбранном направлении «Бланк» (docs/design/blank-direction.md). Клинические функции, источники и права не меняются.

Зависимости: S17I01. Одна сессия. Условие: always.

## Контекст начала

Прочитать START_HERE.md, STATE/DECISIONS/BLOCKERS/EXTERNAL/BUDGET, отчёт S17I01, docs/design/blank-direction.md и .agents/skills/hac-interface/SKILL.md (frontend-design, frontend-ui-engineering, accessibility-checklist). Стек прежний: Flask/Jinja, CSS, обычный JS.

## Что делаем

1. Создать с нуля CSS «Бланк» (apps/compass/static/app.css): токены цвета/типографики/интервалов, каркас с верхней навигацией для обеих ролей, таблицы-журналы, поля с подписями под линией, шкала ответов, метки состояний словом и формой, сообщения об ошибках и пустые состояния, видимый фокус, адаптация 320–1440.
2. Подключить шрифты PT Sans/PT Serif локально из apps/compass/static/fonts (лицензия OFL), без внешних служб; fallback системными. Скачивание файлов — только с прямого согласия пользователя.
3. Применить систему ко всем существующим шаблонам: общие компоненты и разметка base/login/error/dashboard; сохранить точные клинические тексты, роли, CSRF, серверные подтверждения и значения, проверяемые тестами.
4. Снять базовые снимки «до» и «после» и проверить обе роли на всех экранах без потери функций F01–F08.
