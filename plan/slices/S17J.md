# S17J. Локальный поиск по проверенным источникам для RAG

STATUS: PLANNED. Только планирование; реализация не начата.

Основание: прямое уточнение пользователя в S17H — «думаю тут раг система нужна будет умная». Объём отделён до реализации; это самостоятельный поисковый слой, а не обход клинического блокера S17I.

Зависимости: S17H. Одна следующая отдельная сессия. Только сервис; организационные задачи отложены.

## Контекст

Читать START_HERE, STATE/DECISIONS/BLOCKERS/EXTERNAL/BUDGET, последний принятый отчёт, требования/подпункты coverage, FU-spec и ai-decision S17H. До изменений git status/diff, зависимости/источники/права/конфиденциальность/бюджет. Чужие изменения сохранять. Делегированные изменения — только implementation-worker по полному протоколу владения; исследование read-only web-researcher.

## Что делаем

1. Прочитать S17H, FU-spec/ai-decision/source-map и фактическое состояние источников. До изменений назначить точные пути. Реализовать только локальный поиск оснований по проверенному версионированному корпусу, без персональной рекомендации или генератора лечения.

2. Подготовить проверяемый импорт точных КР/ГРЛС: SHA, версия/статус, URL, страница/раздел, показание/возраст/тип документа/права. Недоказанные метаданные и ошибки извлечения — карантин. Архивную версию не выдавать за действующую. Обновление индекса явно, без сетевого скачивания в запросе пациента.

3. Сначала измерить локальный лексический базовый поиск, сохраняющий отрицания/исключения/таблицы и возвращающий точный фрагмент с контекстом и страницей. Проверять применимость и версию. Нет подходящего основания — явный отказ, не память модели и не открытый интернет.

4. Для семантического/гибридного поиска определить конкретного кандидата, права, ресурсы, приватность и сравнение на заранее отделённых синтетических вопросах. Новые модели/платные API/внешняя передача автоматически не разрешены. Если кандидата нет, честно принять только измеренный поисковый базовый вариант и явно сохранить оставшийся объём; не называть его доказанным умным RAG.

5. Проверить оба направления, Авиандр без расширения показаний, неправильный возраст/диагноз, старую версию, неизвестные метаданные, отсутствие ответа/конфликт, разрыв исключения и инструкции внутри текста. Доступ только по прежним ролям, без записи медицинских фактов/плана, отдельная проекция пациенту; интерфейс через hac-interface.

6. Сохранить отдельные измерения качества поиска/ссылок/отказа/ресурсов, проверить обновление/повтор/рестарт/сохранность и make check. Техническая релевантность не клинический эталон; связь с FU/S17I требует фактического независимого заключения.
