# FE03 — Полные наглядные истории десяти пациентов

Статус: PLANNED. Поручение: 27.10.2026. Одна сессия — один срез.
Зависимости: FE02. Общий план: `plan/frontend/README.md`.

## Работа

1. На копии сохранить P201–P210, двух врачей, существующие учётные записи и S55/S56. Составить хронологию каждого пациента: анамнез/приёмы, анкеты, дневник, документы, лекарства/отметки, переписка и врачебные решения.
2. Подготовить версионное дополнение историй по plan/frontend/scenarios.json с четырьмя источниками риска, динамикой диагноза/плана и отрицательными случаями. Новые события добавлять обычными сервисными механизмами; прежние неизменяемые строки не редактировать.
3. Сгенерировать содержательные серверные результаты штатной системой на явно вымышленных сведениях, сохранить происхождение и стоимость. Подготовить начальную точку и отдельные события «после» для воспроизводимого обновления.

## Условия приёмки

- FE03-A01: У каждого из десяти пациентов есть согласованная временная линия; исходные истории/назначения/даты и пароли сохранены, противоречия намеренны и объяснены.
- FE03-A02: Все сценарии D01–D12 имеют точный patient ID, шаги, ожидаемые наблюдаемые состояния и ссылку на фактическое доказательство; набор реально готов до интеграции экранов.
- FE03-A03: Есть содержательные примеры всех трёх функций через настоящие backend/worker/модель в бюджете, а не вручную нарисованные ответы. Вымышленное решение врача помечено как синтетическое; модельное предположение не выдаётся за установленный факт.
- FE03-A04: Повтор подготовки не дублирует события; наличие новых пользовательских записей блокирует разрушительное восстановление. Подготовка и сброс теста ограничены копией.

Прочитать START_HERE/AGENTS, STATE, память решений/блокеров/источников/бюджета, последний принятый отчёт, этот файл и `plan/frontend/SESSION.md`. Проверить источниковые сроки и лимит перед модельными запросами.

```sh
python3 tools/validate_plan.py
python3 tools/session.py status
git diff --check
python3 tools/session.py start FE03
```

`start` выполняется один раз перед работой, остальные команды — до/после. Конкретные существующие целевые тесты выбрать по изменяемым модулям, записать команды и результаты в отчёте; браузерные действия и доказательства каждого Axx обязательны для изменённых экранов. Общий `make check` не запускать автоматически: прежнее поручение об отсрочке сохраняется.
