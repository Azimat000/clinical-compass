# BE01 — Контракты трёх функций и хранение результатов

Статус: PLANNED. Поручение: 26.10.2026.
Зависимости: S56.
Исходные требования (план покрытия, не выполнение): M01, M03, T09, T10, T12.

## Работа

1. Сверить фактические clinical_rules, critical, decisions, medications, followup, worker, источниковые механизмы и миграции. Переиспользовать их; записать карту существующего и нового без второго независимого плана лечения.
2. Реализовать версионированные серверные контракты и хранение анализа: ровно risk, diagnosis, plan; идентификаторы пациента, снимка входов, запуска, источников и состояния результата. Служебные операции не считать четвёртой функцией.
3. Закрепить матрицу поддерживаемых состояний/популяций для первой версии на основе назначения проекта и доступных источников; отдельные ограничения возраста каждого инструмента. Неподдерживаемое возвращает явный статус, не пустой успех.
4. Согласовать общий формат короткого вывода, фактов, противоречий, недостающих данных, источников, ошибок и состояния устаревания. Зафиксировать численные технические бюджеты и протокол измерений до оптимизации.

## Условия приёмки

- BE01-A01: Миграция на отдельной копии сохраняет существующие данные, роли, историю и ограничения; повторный запуск безопасен.
- BE01-A02: Контракт различает queued/running/ready/insufficient_data/unsupported/stale/failed и доступность клинического выпуска; не смешивает эти состояния с отсутствием риска.
- BE01-A03: Существует машиночитаемая спецификация API и примеры всех состояний; входы и выходы валидируются сервером. Пациент не читает внутренние результаты.
- BE01-A04: Матрица области первой версии перечисляет поддерживаемое и исключённое с причинами; все три функции и исходные F/M/E/T/C сохранены.
