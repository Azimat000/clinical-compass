три блока на рабочем сайте, без проверок, максимально быстро; сохранить историю,
стиль, навигацию и остальной интерфейс.

## Выполненные изменения

- Серверный координатор backend_ui_updates: каждые 10 секунд читает текущие
  синтетические истории активных врачебных связей, хранит устойчивый курсор
  diagnosis/plan, создаёт один идемпотентный запрос на сочетание истории/операции/
  связи. Чтение браузером не создаёт запросов. Свой диагноз не считается новым
  симптомом для повторного диагноза; план зависит от актуального диагноза врача,
  рисков и сверки лекарств. Запись результата не запускает сама себя.
- Дополнительная миграция024 содержит только технические курсоры. Прежние
  клинические строки, авторство, версии и журнал не переписываются.
- В диагноз добавлен необязательный код для серверного выбора области плана.
  Ввод врача остаётся в форме; обновление не перепривязывает набранный диагноз
  к новым данным без явного обновления основания/повторного просмотра.
- Лекарственная сверка через BE14: неизвестно/да/нет/противоречие для факторов,

  приём, доза/сила/кратность/форма, ответ/переносимость/первая линия и основание.
  Ни одно отрицание фактора не подставляется из отсутствия текста.
- Редактор BE15: один из серверных лекарственных вариантов, дозировка/сила/
  кратность, явные времена/начало/срок; отдельная ручная оценка направления;

диагностические модельные запросы до действующего допуска качества; на сайте

показана причина, форма сверки остаётся доступна.

и ручных вызовов модели нет. Запущенные рабочие процессы выполняют реальную
функцию с прежними бюджетными/источниковыми/качественными ограничениями;
фактические расходы после запуска без проверок не измерялись.
