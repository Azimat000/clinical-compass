## Реализация

017_backend_jobs.sql: default enabled=0, генерационная версия, leased-задачи,
история попыток; триггеры четырёх источников/исправлений помещают намерение в
прежний outbox атомарно с записью. Модель при сохранении не вызывается;
прежний evaluate_safety остаётся независимым и синхронным. outboxHandler
проверяет точную связь и сводит события одного текущего снимка к одному risk.
Диагноз/план создаются только явным врачебным запросом существующего API.

backend_jobs.py: короткий транзакционный claim, выполнение вне блокировки,
публикация через прежний advance/контракт/источниковые проверки в атомарном
finish. Случайный token/lease90с защищают от старых работников,3попытки,
задержки2/4с, реальный restart/reclaim, отмена с отзывом token. Ошибки только
фиксированные коды, без содержимого исключений/секретов/медицинских текстов.
Перед claim/finish/read снова проверяются доступ/точная связь и свежесть.

backend_analyses.py поддерживает исходную транзакцию outbox, атомарно создаёт
задачу и включает backend_runtime в снимок при enabled. Хеш учитывает версию
исполнения/модели/инструкции/извлечения, данные/источники/дата остаютсяBE02/03.
Изменение или недоказанная свежесть → stale. Снимки не обрезаются,4МиБ-предел
и явная ошибка сохранены; обработку текста внутри будущих клинических
исполнителей этот срез не реализует.

CLI worker --lane risk/generation/all. Для независимости от уже выполняющейся
долгой генерации нужны два процесса risk/generation; all даёт приоритет только
между задачами. Прежний критический outbox выбирается первым. Новых экранов/
