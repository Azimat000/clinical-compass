## Изменения и решения

- backend_snapshot.py: четыре обязательных входа, неизменённые исходные строки
  BE01 и отдельная нормализованная история patient-history-v2. Все версии,
  автор/происхождение/обе даты/источник поля/явные статусы, цепи исправлений.
  Анамнез и текущие жалобы разделены; черновики и историчность явны. Дополнены
  полные тексты/авторство планов, назначения отдельно от фактического приёма.
- Точная ссылка s2_SHA256 связывает таблицу, первичный ключ и полную замороженную
  строку. Поля имеют source_ref/path/value; суммы связаны с assessment_results.
  Чтение проверяет SHA строки и никогда не подменяет её новым содержимым базы.
  Старые таблица:id/profile:id сохранены для совместимости.
- backend_analyses.py/web.py: два новых GET/HEAD только врачу той же действующей
  связи: /api/v1/patients/{patient}/analyses/{run}/inputs (страницы50элементов)
  и /inputs/{reference}. Транзакционное чтение замороженного снимка, no-store,
  ошибки/изоляция; старый BE01-снимок без версии даёт409, не переписывается.
- Нет скрытого LIMIT/обрезки: counts/entry_count/missing_categories/полные части.
  Предел снимка4МиБ даёт явный атомарный409; старый анализ при неподтверждённой
  свежести становится stale. Одинаковые входы не содержат времени вызова/ID запуска.
- backend-api.json дополнен только новыми путями/схемами; Analysis/API1.0,
  прежние пути/схемы не менялись. Проверяющий механизм поддерживает объект
  произвольных полей только там, где additionalProperties=true (исходная строка).
- backend-snapshot.md описывает домен/поля/части/ссылки/ошибки/совместимость/пределы.
  backend-contracts.md ссылается на новый договор. Новая миграция не требуется.

Структурные различия одного кода в один день означают только просьбу сверить
