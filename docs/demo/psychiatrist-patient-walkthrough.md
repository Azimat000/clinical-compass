# Сервис: психиатр и пациент между приёмами

Технический сценарий сервиса S17G от 20.10.2026. Данные и действия вымышленные; это самопроверка, не апробация или медицинский допуск. По прямому поручению пользователя презентации и организационная подготовка отложены для этой и следующих сессий.

## Раздельные кабинеты

Открыть **два отдельных профиля/контекста браузера**: Врач и Пациент. Обычные вкладки одного профиля делят вход и для этого не подходят. В прототипе используются заранее созданные аккаунты и действующая связь одной ведущей пары. Самостоятельная регистрация и обмен карточкой между врачами не реализованы. Не показывать реальные истории, персональные документы или пароли на слайдах.

Для воспроизведения проверки из корня HAC: `node evidence/S17G/browser-preview.cjs`. Скрипт сам создаёт временную синтетическую БД, запускает сервер на 127.0.0.1:18047, проходит оба кабинета в Chromium, сохраняет снимки и удаляет временную БД. Это автоматическая самопроверка, не готовый интерактивный стенд для встречи. Для интерактивного запуска использовать `docs/RUNBOOK.md`; проверка не меняет рабочую БД. Снимки сохраняют действительные состояния обеих ролей.

## Основной сервисный путь

Цель продукта — собрать к повторному приёму исходные сведения пациента, даты, ответы, нежелательные явления (НЯ) и выполнение плана. Польза для врача — продуктовая гипотеза; экономия времени и клиническая эффективность не установлены.

| Шаг | Исполнитель и вход | Реальный экран / действие | Результат и доказательство |
|---|---|---|---|
| 1. Приём | Ведущий психиатр, связанная карточка D01 | «Наблюдение», сведения и источники; при отсутствии диагноза доступен отдельный «Первый приём без готового диагноза» | Реальная карточка: `evidence/S17G/01-doctor.png`. Четырёхшаговый первый приём принят S17E; здесь заново не объявляется реализованным |
| 2. Домашняя оценка | Психиатр, вкладка «Анкеты» | Указать 35 лет и источник **вымышленного** возраста → «Предложить DASS-42» | Конкретный запрос связанному пациенту. Ограничение демо: сверенный известный возраст 18–120; действует сегодня и максимум 24 часа. Не общий клинический возраст применения |
| 3. Ответы дома | Пациент в другой сессии → «Анкеты» | «Заполнить предложенную DASS-42», 42 точных вопроса → «Передать анкету врачу» | `02-patient-questions.png`, `03-patient-receipt.png`. Пациент получает квитанцию без вычисленных баллов и интерпретации. Пропуск допустим, тогда ни одна сумма не рассчитывается |
| 4. Просмотр | Ведущий врач → «Анкеты» | Исходные 42 ответа, три отдельные суммы, версия и дата | `04-doctor-results.png`, `05-doctor-dynamics.png`. В проверке ответы «2» дали 28/28/28, ответы «1» — 14/14/14. Два ввода **в один день**, не результат лечения и не клинически значимое улучшение. Общего балла/диагноза/автоматической интерпретации нет |
| 5. Решение врача | Врач → «Решения врача» | Справка; вручную ввести проект «Изменение плана», основание и неизвестность, затем отдельно подтвердить точную версию | `06-reference.png`, `08-approved.png`. В проверке только условный план дневника; лекарственная терапия не назначается. Сохранённый проект не действует до подтверждения |
| 6. Выполнение дома | Врач задаёт пункт из подтверждённого плана; пациент открывает «Сообщения и выполнение плана» | Врач отдельно подтверждает пункт/время; пациент отмечает пропуск с причиной и пишет сообщение | `09-patient-progress.png`, `11-doctor-followup.png`. В проверке пункт — запись в дневнике, не лекарственная доза. Нет сведений и противоречие не считаются пропуском |
| 7. Дневник | Пациент → «Добавить самоотчёт» | Дата, субъективное самочувствие, жалобы, НЯ, приём/пропуски, при наличии источник возраста | `10-patient-diary.png`; запись видна врачу после открытия «Посмотреть динамику». Запись на сервере не означает прочтения/реакции; обычный канал не обеспечивает экстренную помощь |
| 8. Повторная оценка | Психиатр → динамика, сообщения, выполнение, источники | Сопоставить одинаковую форму/версию/ключ; отдельно дневник, НЯ и пропуски, затем собственное решение | Существующие сведения видны в двух кабинетах. Новое основание требует пересмотра старого проекта перед подтверждением. Из корреляции нельзя заключать о причине изменения |
| 9. Следующая доработка | **Будущее S17H/I** | Обоснованный проект следующего действия по данным наблюдения | Экрана и реализации новых рекомендаций пока нет. Сначала точные источники и применимость, затем фактическая независимая клиническая проверка и реализация. ИИ не подключён |

Все изображения в таблице после первой строки находятся в `evidence/S17G/`. Точные результаты и версия браузера — `browser-results.json`. Снимки — записи фактического состояния этого прогона, а не макеты будущих функций.

## Дополнительный вход через терапевта

Терапевт может начать с жалоб без готового диагноза; соматические причины оценивает врач. F08 сохранена: «Решения врача» → «Направление», категории «Обязательно»/«Желательно», основания/неизвестность и отдельное подтверждение. Экран `07-referral.png`. Категорию и срочность не выводить из одной DASS; новые ветви первого обращения остаются в blocked S17D. Не показывать вымышленную передачу карточки психиатру: сейчас одна ведущая пара, совместное ведение не реализовано. Прямой приём психиатра допустим для этого показа.

## Срок отправки в сервисе

В списке предложений и в форме теперь показано «до ДД.ММ.ГГГГ ЧЧ:ММ МСК» с машиночитаемым элементом time. Срок — более ранний из expires_at и следующей полуночи Москвы после дня сверки возраста. Например, запись expires_at 21.10 18:00 UTC при age_on 20.10 даёт предел 21.10 00:00 МСК. Необработанные 24 часа из базы показывать как срок пациенту было бы неверно.

Новый текст сохраняется при ошибке ввода. Истёкший запрос по-прежнему отклоняется сервером, открытая вкладка срок не продлевает. Исходные вопросы/инструкция/варианты и ключ DASS не изменены. Снимки до/после и 320px — evidence/S17G/. Презентации, организация встречи/сдачи и сообщения людям в текущий результат не входят.
