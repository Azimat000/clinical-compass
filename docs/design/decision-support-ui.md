# Три блока поддержки решений · FE01

27.10.2026. Режим **Operate**: врач проверяет сведения, записывает собственное
решение и отдельно подтверждает изменение плана. FE01 — проверенный UX-прототип,
не подключённая функция. Рабочие страницы и данные не изменяются.

## Граница и визуальное основание

Авторитет внешнего вида — текущие `dashboard.html`, `doctor_patient.html`,
`decisions.html` и `static/app.css` из baseline FE01. Сохранены PT Sans/PT Mono,
белый лист, угольная шапка, тонкие разделители, существующие поля/кнопки/раскрытия.
Красный только у причины критического сигнала; ожидание и ошибки — словами и
линиями. Не добавляются новый стиль, меню, общий счётчик, отдельная страница
уведомлений, анимация или библиотека. Старые решения S31/S39 отменяются только
в части прямо порученного нового блока сигналов.

**THESIS:** рядом с существующей работой врача показывать предложение, его
основания и границы; собственный текст врача и действующий план различимы.
**OWN-WORLD:** существующий «Лист результатов», без новой визуальной системы.
**STORY:** сигнал → точный источник; гипотеза → собственная формулировка;
предложение плана → проект → отдельное подтверждение.
**FIRST VIEWPORT:** список сохраняется, справа виден сигнал; в карточке обе
подписи диагноза рядом по вертикали; в плане первым остаётся действующее решение.
**FORM:** обычные ссылки, текстовые поля, кнопки, details; узкие экраны — одна колонка.

Файлы прототипа: `prototypes/FE01/{signals,diagnosis,plan}.html`, `support.css`,
`support.js`. Верхняя панель «Прототип FE01» — только инструменты просмотра,
не проект нового меню приложения. Все новые правила ограничены `.fe01-*`.
Исходные страницы находятся в `prototypes/FE01/baseline/`; CSRF и ключи повторов
удалены из снимков, пробелы в конце строк нормализованы для Git. Макет работает только на локальном read-only сервере:
`python3 evidence/FE01/serve.py` → `http://127.0.0.1:8061/`.

## Серверные операции: существующее и ещё требуемое

Основание карты — непосредственно `apps/compass/web.py`,
`backend_alerts.py`, `backend_diagnosis_review.py`, `backend_plan_review.py`.
Это локальные контракты BE16, не результат внешнего поиска документации.
`p`, `run`, `alert`, `proposal` ниже — точные серверные идентификаторы.

| Действие | Существующая операция | Условия интерфейса |
|---|---|---|
| Лента врача | `GET /api/v1/physician/alerts?page=N` | Только свои пациенты; страницы, версия эпизода, время события/доставки/проверки различаются. Нет обещания мгновенной доставки. |
| Подробности сигнала | `GET /api/v1/physician/alerts/{alert}` | Причина, тип источника, точные ссылки, история действий. Дневник, анкета, анамнез и приём — разные подписи источника. |
| Рассмотрение сигнала | `POST /api/v1/physician/alerts/{alert}/actions` | `received → seen → processed`, строго по ответам сервера; `expected_revision`, `request_key`, `reason`. Для processed обязательно содержательное основание. Received после показа, seen после явного открытия содержания; не отправлять из обычного GET. Processed — явная кнопка врача, не автоматическое последствие перехода. Новая версия не закрывается старой отметкой. |
| Создание анализа | `POST /api/v1/patients/{p}/analyses` | Проверенный запрос diagnosis/plan, права, снимок, ключ повтора, лимиты. Обычное чтение никогда не вызывает создание. |
| Состояние / основания | `GET /api/v1/patients/{p}/analyses/{run}`, `…/inputs`, `…/inputs/{reference}` | Дата/версия/снимок; точная запись или ответ, автор/время/редакция. Ссылки строить из разрешённой серверной проекции, не угадывать номер записи. |
| Подробности гипотезы / риска | `GET …/analyses/{run}/diagnosis-context`, `…/risk-context` | Подтверждённые, отсутствующие, неизвестные и противоречивые критерии; исходная модельная цитата не становится фактом. |
| Прочитать диагноз врача | `GET /api/v1/patients/{p}/diagnosis-review?page=N` | `head_version`, `snapshot_id`, `current.fresh`, receipt и история. Устаревшая запись остаётся исторической, не основанием нового плана. |
| Сохранить собственный диагноз | `POST /api/v1/patients/{p}/diagnosis-review` | Основной путь `action=manual`: собственный diagnosis ≤2000, необязательный код, basis/uncertainties ≤4000, reviewed=true, request_key, expected_version, snapshot_id; run/revision/hypothesis null. Серверные accept/modify/reject сохраняются, автоматическое принятие гипотезы не добавляется. |
| Сверка лекарственных сведений | `GET/POST /api/v1/patients/{p}/therapy-context` | При необходимости раскрываемая форма внутри нового блока плана: назначенное/фактическое/отменённое, эффект/переносимость и неизвестное. Только явная запись врача; не извлекать безопасную дозу из свободного текста браузером. |
| Создать проект решения | `POST /api/v1/patients/{p}/analyses/{run}/plan-reviews` | Выбранные item IDs/даты, допустимый кандидат medication либо null, routing либо null, basis/uncertainties, reviewed, snapshot/revision, expected_version/parent_id/request_key. Сервер заново проверяет пригодность. |
| Прочитать / подтвердить проект | `GET/POST /api/v1/patients/{p}/plan-reviews/{proposal}` | POST: version, approved/rejected, rationale, reviewed=true. Только успешный ответ изменяет текущий план/календарь через прежний серверный журнал. Нет второго журнала в браузере. |
| Отмена анализа | `POST …/analyses/{run}/cancel` | Пустой JSON, права/CSRF; отмена анализа не отменяет лечение. |

**Не объявлено существующим:** список последних анализов пациента, автоматическое
восстановление пропущенных событий, согласованный HTML-адаптер для новых форм,
автоматическая координация diagnosis/plan. FE02 определяет минимальные чтения
и адаптеры по коду. FE06/FE07 обеспечивают событие → проверка достаточности,
источников и бюджета → один анализ актуального снимка. Собственная запись
анализа не запускает цикл генерации. Автоматический риск использует свою очередь
BE06 независимо от медленной генерации плана.

## Содержимое и переходы

**Сигнал.** Полное имя/код, конкретная причина, источник, время и редакция;
ссылка на точный источник, раскрытие рассмотрения и история. Пустая лента
сообщает «Новых сигналов нет» с временем успешной проверки, не «Риска нет».
При ошибке нет нулевого счётчика. Исторический эпизод явно датирован и отделён
от текущего. Пропуск, частичный приём и отсутствие отметки не объединяются.
При большом количестве — серверные страницы и «Ещё сигналы», без сортировки
всей истории в браузере. Порог риска интерфейс сам не вычисляет.

**Диагноз.** Гипотеза, ограничения и основания выше собственной формулировки
врача. Новое вычисление не перезаписывает текст врача, даже если совпадает по
смыслу. Врач явно сохраняет формулировку с основанием, неопределённостью и
отметкой просмотра. Ни генерация, ни сохранение диагноза не назначают лечение.
История записей врача отдельна от версий анализа. Без пригодной гипотезы
собственная запись допустима только при доступном актуальном серверном снимке;
ошибка модели сама по себе не запрещает врачу писать. Макет переключателя
показывает консервативную блокировку записи во всех неготовых состояниях;
точную независимость этих операций проверяет FE06.

**План.** Наблюдение/обследование/направление и лекарственный вариант отображаются
раздельно. Разрешённый вариант содержит реальные серверные наименование,
форму/силу/дозу, путь и частоту, длительность/дату, фазу терапии, противопоказания,
взаимодействия и ссылки на точные версии источников; unknown/block видны словами.
В FE01 положительный лекарственный результат не выдумывается: показано
«новый лекарственный вариант не предложен» и конкретная нехватка сверки.
Проект наблюдения присутствует. В FE03 положительный пример должен поступить
из настоящего поддержанного backend, а не из этих HTML-файлов.

«Подготовить решение» раскрывает выбранные пункты, изменения относительно
текущего плана, врачебные даты и обоснование. Создание проекта и подтверждение —
две операции. При редактировании поддержанные поля проверяются сервером;
произвольная смена лекарства/дозы не проходит как «тот же кандидат».
Сохранённый неподтверждённый проект не меняет лечение. После подтверждения
обновляется существующий текущий план; пациент видит только утверждённое.
После отклонения — «Отклонено врачом; план не изменён». История неизменяема.

## Состояния только новых блоков

| Состояние | Видимый смысл и действие | Что сохраняется |
|---|---|---|
| ready | Результат + время, версия, основания. Доступно явное рассмотрение. | Врачебный текст и действующий план независимы. |
| queued / running | «В очереди» / «Анализ выполняется», без обещания срока. | История доступна; нет повторного запуска при опросе. |
| partial / insufficient_data | Конкретно недостающие сведения и ссылка на имеющийся экран ввода. | Пропуски не нули, диагноз/доза не подставляются. |
| unsupported | «Вне поддержанной области» с серверной причиной; нет кнопки применить. | Источники/история доступны, врач может продолжать обычную работу. |
| stale | Старая версия только для сравнения; указать новые сведения или истёкший источник. | Текст врача не стирается. Применить старое нельзя. |
| failed / cancelled | Понятная причина и допустимый явный повтор/новый запрос. | Отсутствие результата не трактуется как отсутствие риска. |
| offline / неизвестная свежесть | Последнее успешное время и «Свежесть неизвестна». | Не отправлять сохранение автоматически при восстановлении сети. |
| empty | «Результата пока нет» / «Новых сигналов нет» после успешного чтения. | Нет утверждения благополучия. |
| saving | «Сохраняется…», кнопка временно недоступна, aria-busy. | Ввод остаётся; ключ повтора тот же для той же отправки. |
| saved | Автор/время/версия только по receipt сервера. | После получения успеха явно обновить текущую проекцию. |
| conflict | «В другой вкладке сохранена новая версия». Сравнение своей и серверной записи. | Не перезагружать всю форму; не объединять тексты автоматически. |
| validation error | Ошибка у поля, введённые значения остаются, ссылка/фокус на ошибку. | Повтор после исправления с проверкой серверной версии. |
| access_denied / session expired | Скрыть защищённое содержимое; предложить вход/своих пациентов. | Не показывать чужие данные и не переносить текст другому пациенту. |

В прототипе 13 переключаемых состояний; unsupported описан как отдельная причина
неполноты, без нового клинического правила. Ошибки не окрашиваются в клинический
красный. Успех выбирается отдельно на панели просмотра, не имитируется таймером.

## Доступность и обновление

Заголовки и label связаны с полями; источники — обычные ссылки. Новые элементы
доступны с клавиатуры, область кнопок/раскрытий ≥44 px, видимый штатный фокус.
Текст переносится, новые блоки не обрезаются и не требуют горизонтальной прокрутки.
Цвет подкреплён словами. Анимация не добавлена; reduced-motion не меняет смысл.
Изменения статуса сообщаются через status/alert, без переноса фокуса при фоновом
обновлении. Пока врач печатает, обновляется сообщение, а не вся форма.

Без JS прототип читается и раскрывает details; сохранение в нём отсутствует.
Будущая интеграция обязана иметь обычный серверный путь формы и ручное обновление
страницы, без скрытой генерации в GET. Опрос ограничен, приостанавливается в скрытой
вкладке, не запускает анализ. Интервал/таймаут — измеряемые решения FE02/FE05,
не характеристика FE01. Не использовать localStorage/sessionStorage для истории.
