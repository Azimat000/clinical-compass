# Бриф нового интерфейса «Клинический компас»

22.10.2026. Прямое поручение пользователя: построить новый интерфейс с чистого листа. Это исходные данные для `/impeccable init` (он пишет PRODUCT.md после короткого интервью) и для выбора направления в UI01. Не визуальный образец: внешний вид решается в UI01 выбором пользователя.

## Слова пользователя

> Твоя цель построить идеальный фронтенд, интерфейс, дизайн и UX/UI. Чтобы это не выглядело иишно, а сразу красиво и достойно. […] Это должен быть самый простой, наглядный и удобный интерфейс для пользователей, без лишних слов.

Отсюда четыре проверяемых требования к каждому экрану:

1. Простой: одно главное действие на экране видно сразу, без прокрутки на телефоне.
2. Наглядный: состояние понятно по виду (цвет, форма, число, график), а не по абзацу текста.
3. Удобный: путь до результата короткий, ошибки исправимы, повтор безопасен.
4. Без лишних слов: подписи короткие, пояснения только там, где без них ошибутся; нет маркетинговых фраз и «ИИ-текста».

## Кто пользуется

- **Пациент** дома, чаще с телефона: отмечает самочувствие (самоотчёт), заполняет анкету DASS-42 по запросу врача, читает и пишет сообщения. Может быть уставшим, тревожным, плохо видеть мелкий текст.
- **Ведущий врач-психиатр** на приёме за компьютером (иногда планшет): видит, кому нужно внимание, открывает карточку, готовит повторный приём по сводке, принимает и подтверждает решения, проводит первый приём, загружает документы, отвечает на сообщения, реагирует на критические события.

Основной путь: психиатр → самостоятельная работа пациента дома → повторный приём.

## Жёсткие ограничения

- Стек сохраняется: Flask/Jinja, свой CSS, обычный JS без фреймворков и сборки. CSP `default-src 'self'`: никаких CDN, внешних шрифтов, inline-скриптов и inline-стилей. Шрифты — локальные файлы с лицензией.
- Клинические границы не трогает дизайн: назначение, изменение или отмена терапии, направление и изменение плана — только после подтверждения врача на сервере. Интерфейс показывает подтверждение только после ответа сервера.
- Пациент не видит вычисленных сумм и интерпретации DASS; текст и порядок вопросов DASS не меняются.
- Неизвестное, пропуски и противоречия видны как таковые; отсутствие данных не выглядит как «всё хорошо».
- Самоотчёт: личный черновик на сервере, защита повторов и вкладок, без localStorage/sessionStorage, без автоматического повтора; без JS форма работает.
- Данные в прототипах и снимках только синтетические (учебные истории WD01–WD05).
- Русский язык, доступность не ниже WCAG 2.2 AA, телефон от 360 px, компьютер до 1920 px.
- Удалённый в S29 интерфейс и его снимки не являются образцом.

## Чего избегать (признаки «ИИ-дизайна»)

Детектор impeccable и правила design-taste-frontend ловят большую часть автоматически. Для этого проекта особенно: градиенты и свечения, иконки в цветных квадратиках, ряды одинаковых карточек, «hero» с крупным лозунгом, капсулы-подписи над заголовками, выдуманные числа и отзывы, декоративные эмодзи, длинные поясняющие абзацы.
