# Полная история в ограниченных запросах — FE03A

FE03A — внутренний подготовительный механизм `context-packets-v1`.
Он не подключён к HTTP/worker/обычному генератору и не устанавливает диагноз.
FE03 разделён до реализации на A (вход), B (выполнение/агрегация/качество),
C (исходные примеры D01–D12). Все исходные FE03-A01–A04 остаются у C/родителя.
Остальной интерфейс, рабочий сайт8000/015 и существующие quality gate сохранены.

## Причина

Точный снимок P201 из FE02 содержит279единиц четырёх источников:
159актуальных версий и120предыдущих. Текстов40861байт, уникальных7877байт.
Повтор — в основном один и тот же текст в нескольких версиях. Две ветви
диагностики передавали62166/63532байт при лимите16000; расчётный резерв70358/
71724microUSD также превышал20000. Выбрать лишь последние версии значило бы
убрать часть истории из контекста. В FE03A ни одна версия не исключается.

## Обратимое представление

`backend_context_packets.prepare(payload, schema, config)` получает полный
исходный named-facts-v5 payload. Источником истины остаётся прежний замороженный
снимок и точные unit_id, не транспортная копия.

1. Совпадающие тройки `(text,categories,code)` хранятся как одна группа. Для
каждого повторения остаются отдельные unit_id, исходная позиция и индекс его
метаданных. Положительное/отрицательное/пустое/неизвестное различаются точно;
сходство по смыслу не используется.
2. Пакет содержит только используемые им метаданные с явной картой исходных
индексов. Даты/статусы/признак текущей версии не удаляются. Полная исходная
таблица метаданных, включая неиспользованные строки, остаётся в серверном
манифесте восстановления. Текст хранится строкой целиком, без суммаризации,
усечения, нормализации пробелов, Unicode или чисел.
3. Группы упаковываются в исходном порядке первого появления. Перед добавлением
каждой группы вызывается прежний точный `backend_model.preflight`, учитывающий
system prompt/схему ответа/максимальный вывод/резерв, а не только длину текста.
В расчёте заранее заложены самые длинные номера пакетов. Максимум64пакета.
4. Каждый пакет содержит исходный хеш/номер/количество/полноту; собственный
хеш закреплён отдельно в серверном манифесте. `restore(plan,expected_sha256=...)`
восстанавливает полный исходный payload, проверяет все позиции/единицы/версии,
недостачу/повторы/перестановку/порчу и сравнивает канонический JSON-хеш.
Ожидаемый хеш должен приходить из доверенного исходного снимка отдельно,
а не из потенциально изменённого манифеста. Хеши не заменяют подпись/авторизацию.

Поля пакета `columns=[text_index,categories,code,occurrences]`,
`occurrence_columns=[unit_id,original_position,metadata_index]`; text_index
указывает на texts, metadata_index на локальную metadata. Вступление к заданию
явно объясняет кодирование и неполноту каждого отдельного пакета.

Если заголовок/схема, одна полная группа или количество пакетов не проходят
лимит — явный `PacketError`, без возвращения частичного плана и без усечения.
Ошибка содержит код/индекс, без клинического текста/секретов. Таков ограниченный
поддерживаемый формат; огромная одиночная запись пока не разбивается на куски.

## Реальная проверка десяти историй

`evidence/FE03A/full_history.py`: штатный SQLite backup в0600
`var/FE03A-grouped-sizing.sqlite3`; действующие миграции применяются только
там. На P201–P210 и обеих диагностических ветвях полное обратное восстановление
равно исходному входу, старые версии сохранены. 20ветвей/92пакета; 4–6пакетов
на ветвь. Каждый проходит прежние16000байт/20000microUSD,1536выходных токенов.
Наибольший пакет11803байт: здесь резерв стоимости ограничивает раньше16000.

P201:4+5пакетов вместо двух больших запросов, максимумы11795/11799байт;
общий перспективный консервативный резерв176884microUSD. Это расчёт предела,
не фактическая стоимость, не списание и не обещание времени выполнения.
У всех10пациентов суммарный перспективный резерв выше остатка251933microUSD;
нельзя запускать весь набор без отдельного бюджетного плана. Общий cap1000000
и percall20000 не повышались; budget reserve/сеть/DeepSeek не вызывались.

Первая упаковка без группировки потребовала188пакетов, P20120вызовов и394549
microUSD потенциального резерва. Сохранена в initial-full-history.json/log как
результат отвергнутого варианта, а не дополнительный принятый прогон модели.
Финальный результат — full-history.json. Рабочие строки/доступы/модельный ledger
не менялись; копия после вычислений также не получила новых строк.

## Обязательные границы следующего FE03B

Это доказательство полноты и размера входа, не эквивалентность решения модели.
Девять пакетов P201 нельзя просто опубликовать как девять диагнозов. FE03B:

- обрабатывает весь зафиксированный манифест либо возвращает явную неполноту;
не публикует успех отдельных пакетов как завершённый анализ;
- проверяет цитаты по исходным unit_id/точным версиям, сохраняет противоречия
между пакетами/датами и неизвестность; локальное отсутствие факта не делает
его глобально отсутствующим;
- отдельно проверяет длительность и причинные основания полного синдрома,
совместимость наблюдений и текущесть, не соединяет разные эпохи в диагноз;
- удерживает прежние пределы бюджета, учитывает все фактические вызовы/повторы,
общий deadline/lease/cancel; проверяет стоимость до запуска, не только в конце;
- подтверждает качество на настоящей модели и защитном наборе до смены runtime
и активации default executor. Прежний успешный gate автоматически не переносится.

Имена критериев и full-history transport не заменяют клиническую экспертизу.
Риск/план/терапия по-прежнему идут прежним механизмом; сценарии FE03C ещё planned.
Источниковый срок BE03до27.10.2026 19:17МСК не продлён. На этом offline этапе
новых медицинских правил/внешних фактов/исследований не требовалось. До любой
генерации FE03B нужны актуальная первичная сверка и ledger. Clinical release blocked.

Для безопасной повторной проверки существующей копии:
`.venv/bin/python evidence/FE03A/full_history.py --verify-existing`.
Используется SQLite mode=ro, без переподготовки/миграций/сброса данных.
