# Источниковые правила S09

Три новые append-only таблицы:clinical_contexts(врачебные факты/автор/источник/связь/дата),clinical_rule_evaluations(снимок входов/применимости/выпуска и результат),critical_events(источниковое событие с адресатом и outbox). Новая миграция008 не изменяет001–007/прежние строки. Никакой фиктивный reviewed_by в общем каталоге не создаётся. Исторический неактивный каталог не переименован в клинически одобренный: отдельный выпуск явно исполняется только в синтетическом режиме сclinical_validation=false.

`release()` проверяет локальные SHA и объёмы двух фактически используемых PDF; fingerprint включает манифест и код. Смена/потеря источника блокирует новую оценку/подтверждение с явным409,а не включает другой источник. Веб не получает источники из сети во время работы. Docker включает ровно два нужных публичных документа по тем же путям; вся папка evidence не копируется.

`save_context` проверяет текущего врача/связь/синтетический профиль,сохраняет уже существующие врачебные факты с источником и снимком автора. Повтор того же ключа не меняет автора/данные,изменённое тело409. Нового назначения/диагноза таблица не создаёт.

Новый пациентский self_report с medication_safety имеет schema_version3;старое тело без safety_form_version остаётся schema_version2 и не переоценивается задним числом. Неполнота и отрицание различаются. После записи исходного отчёта та же транзакция вычисляет оценку и при совпадении создаёт единственный critical_event/outbox. Ошибка на любом шаге откатывает всё. Неактивный/отсутствующий адресат не препятствует сохранению safety-отчёта;обычная доставка вызывается только для доступного активного врача.

Оценка возраста использует все существующие источники и явную актуальную сверку ages.py;диапазон18–19не выбирается как≥19. Новая возрастная информация проверяется повторно. Контекст/наблюдение сегодняшнего дня — консервативная область демонстрации текущих фактов,не измеренная клиническая давность.

Критический outbox ждёт S10,обычный worker не пробует отсутствующий потребитель. Статус critical_event фиксирует только состояние создания pending_s10/unassigned;это не доставка. История положительных событий не закрывается поздним отрицанием. Внутренние источники/критические оценки доступны только ведущему врачу,пациенту — его исходные сообщения и общий источниковый текст без внутренних врачебных фактов.

Рекомендация направления рассчитывается по источнику,но не создаёт care_action. GETfrom_context заполняет врачебную форму,POST сохраняет ID/снимок рекомендации вместе с выбранными врачом полями. Срочность остаётсяunknown до ввода врача. Отдельный confirm использует прежние серверные проверки и снимок,теперь включающий новые таблицы/выпуск. Старые подтверждённые решения остаются;старые незавершённые проекты требуют новой редакции.
