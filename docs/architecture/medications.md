# Ручное расписание препаратов — S33

Врач: карточка → «План и решения» → «Новый проект» → «Препараты в плане» → «Задать новый состав препаратов». Название включает дозировку/форму; начало и длительность задаются вручную, конец включительно вычисляется из них. До четырёх приёмов с точным временем по Москве; количество на каждый приём с шагом ¼ таблетки. Итог таблеток за день — сумма, не отдельное противоречащее поле. Технические пределы формы: 8 препаратов, 4 приёма каждого, 1–366 дней, до 20 таблеток на один приём. Эти пределы не являются медицинскими рекомендациями или допустимыми дозами.

Состав хранится в неизменяемом proposals.payload_json.medications, включая пустой список для явно отменённого расписания. Проект не активен до doctor_confirmations.approved + care_actions; общая проверка актуальности сведений/источников/дня и связь с врачом сохранены. Отдельная проверка med_base защищает редактор от подтверждённого в другой вкладке состава. Врач явно подтверждает проверку названия, дозировки, возможности дробления, времени и курса по источникам и сведениям пациента; содержание препаратов и их пригодность сервис не вычисляет. Общие обязательные основание/неизвестность и отдельное обоснование подтверждения сохраняются. Для therapy_* сохраняется существующая проверка терапии. При therapy_stop с прежним непустым составом требуется явное изменение расписания, чтобы не оставить его случайно действующим.

Обычный план без поля medications сохраняет прежнее расписание. Явный новый состав полностью его заменяет: продолжаемые препараты нужно включить. Направление не может менять состав. Расписание начинается не раньше момента подтверждения: более ранние приёмы не возникают задним числом. При замене старые приёмы до точного времени подтверждения остаются; будущие берутся из нового состава. Курс может начинаться позже подтверждения; после включительного конца приёмов нет.

Календарь строится чтением, по семь дней с выбором дня и переходом ±7 дней, общий для пациента и врача. Есть отдельное раскрытие текущего состава, полного курса и суточного количества. Последний подтверждённый текст решения показан и на главной пациента; черновики, отклонения, врачебные основания и неизвестность в эту проекцию не попадают.

Ключ отдельного приёма: proposal_id + med_index + slot_index + dose_on. medication_marks хранит фактически принятое количество в четвертях таблетки (целое actual_quarters), дату приёма по расписанию, реальное время записи, автора, request_key и возрастающую sequence. NULL означает «убрать отметку», 0 — явный пропуск, 0 < количество < назначенного — частичный приём. Время фактического проглатывания не измеряется. Данные — слова пациента, а не подтверждение врача. Для количества больше назначенного форма не предназначена; описание фактов остаётся в самоотчёте/сообщениях. Советов о компенсации пропуска нет.

Только свой пациент при действующей связи двух включённых кабинетов может записать отметку; врач только читает. До назначенного времени по Москве отметка запрещена. Исправления дополняют историю, UPDATE/DELETE запрещены триггерами. Один request_key повторяет тот же результат; другой текст под тем же ключом отвергается. revision защищает от перезаписи новой отметки устаревшей вкладкой. Все проверки и запись выполняются под BEGIN IMMEDIATE; событие технического аудита атомарно. Новые отметки делают старый неподтверждённый проект требующим повторного просмотра.

Пропуск не выводится из молчания. «Нет отметки» сегодня отображается у уже наступившего приёма, в недельном счётчике отдельно считаются только прошедшие дни; будущие помечены «Предстоит». У врача карточка и экран решений показывают календарь/историю, список пациентов — конкретные пропуски, частичные дозы и дни без отметок за последние 7 дней со ссылкой к первому дню для проверки. Старые недели доступны календарём. Это организация записанных фактов, без клинического риска/балла и без автоматических уведомлений.

Проверки: apps/tests/test_medications.py, evidence/S33/acceptance.md. Новых клинических источников, лекарственных рекомендаций и прав на тексты не вводилось. Медицинская валидация и реальная апробация не выполнены; действуют прежние ограничения проекта.
