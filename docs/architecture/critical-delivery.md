# S10: критическая доставка в локальном синтетическом прототипе

Используется только уже принятый A02-v2. Признаки/возраст/источники и исходная миграция008 не меняются. Протокол текущего транспорта — docs/clinical/critical-protocol-v2.md. Условие существования резерва: отдельная открытая консоль на Unix/macOS, её процесс работает с той же БД и настроен на исходного врача. Это локальный демонстрационный канал, без внешних SMS/email/дежурства.

## Очередь и журнал

Запись отчёта/оценки/critical_events/outbox по-прежнему атомарна в records.save. Новый штатный обработчик принимает тему clinical.critical.medication_safety.v1 и создаёт critical_delivery + ready-журнал одной транзакцией с обработкой outbox. Повторная выдача события использует исходный уникальный ID; новая миграция009 добавляет только две таблицы и неизменяемый журнал. Исходное delivery_state=pending_s10/unassigned — неизменяемый снимок S09, а не текущий статус транспорта. Текущий статус читается из critical_delivery/outbox; CLI delivery-status показывает оба.

BEGIN IMMEDIATE сериализует выбор/обработку события двумя процессами. SAVEPOINT откатывает частично подготовленное уведомление. outbox_attempts сохраняет каждую попытку, её время/исход/класс ошибки; задержки2/4/8/16с, пятая ошибка оставляет dead. Ничего не удаляется. Это инженерные параметры, не медицинский срок. Внешний вызов не находится в транзакции сохранения отчёта.

Без адресата или при отключённом враче событие сохраняется и готовится как техническая запись, но не выдаётся другому врачу. Исходная связь обязательна для API/страницы/отметок/резерва. Автоматического переназначения нет. CLI delivery-status показывает unassigned/recipient_unavailable и ошибки без пациентского текста. Ошибки outbox — таблица outbox_attempts; действия/резерв — critical_delivery_log.

## Состояния

| Поле | Фактический смысл |
|---|---|
| clinical_entries.recorded_at | Приём отчёта сервером |
| ready_at | Уведомление подготовлено обработчиком |
| received_at | Авторизованный браузер отправил квитанцию после двух кадров отрисовки, при видимом документе и пересечении баннера/карточки с областью просмотра; либо врач явно подтвердил отображение |
| seen_at | Отдельная явная отметка врача |
| acknowledged_at | Врач отдельно принял к работе |
| reacted_at/reaction | Врач отдельно записал фактическую реакцию |
| reserve_state=operator_received | Локальный оператор ответил SIGNAL в консоли либо нажал точную кнопку отдельного macOS-окна; личность врача этим не установлена |

GET/HEAD/API чтения не меняют получение/просмотр/реакцию. JavaScript опрашивает /api/critical каждые3секунды при видимом документе, показывает заметный закрепляемый баннер, после отрисовки посылает CSRF-защищённую квитанцию. После принятия врачом к работе баннер исчезает, история/незаписанная реакция остаются на странице сигналов. При сетевой ошибке виден текст неподтверждённой связи. При отключённом JS есть ручная кнопка получения; автоматический сигнал отсутствует.

Квитанция — свидетельство клиентского отображения, не физического экрана/внимания человека. Браузер может быть закрыт, перекрыт другим окном, устройство — спать. Нет ограниченного срока ответа человека или клинической чувствительности. Все POST проверяют серверную сессию/роль/CSRF/исходную действующую связь. Отметки идут строго по порядку, повтор сохраняет первые времена и единственный журнал. Первую реакцию нельзя перезаписать другим текстом. Запись реакции не создаёт/не меняет care_actions, подтверждения решений, терапию или направления.

## Локальный резерв

reserve-console --recipient <doctor-id> работает отдельно от веб-сервера, раз в секунду проверяет очередь. В transaction захватывает событие на35с с уникальным lease-токеном, пишет начало; затем освобождает блокировку БД. До действия повторно проверяет адресата. Выводит только общий сигнал, требует настоящий TTY для stdin/stdout; точный SIGNAL за20с — отдельная квитанция местного оператора. В pipe не изображает успех. BEL передан терминалу, слышимость звука не подтверждается. Для видимости физическому человеку консоль должна быть открыта перед ним; проверка PTY этого не доказывает.

Тайм-аут/ошибка оставляют pending, инженерные повторы с задержкой до60с; после пяти завершившихся неудач — dead с сохранением события/журнала. После аварии процесса lease истекает, повтор возможен; видимый сигнал может повториться, поскольку атомарности между ОС/терминалом и БД нет. Устаревший lease не перезаписывает нового владельца, пишет reserve_lease_lost. Уже подтверждённый местный сигнал не повторяется, но не становится врачебной реакцией. Погибшие до записи исхода попытки сохраняют reserve_started; их число может превышать5 при повторяющихся авариях — событие не выбрасывается. Подтверждение врача прекращает новые резервные попытки; уже показанный сигнал может ещё закрываться.

reserve-macos — дополнительный непроверенный на физическом экране путь. display dialog с фиксированным общим текстом ждёт20с; запуск ограничен25с. Только точная кнопка и gave up:false дают местную квитанцию. В этой сессии положительная реальная доставка окна не подтверждена: попытка завершилась неуспешно; ошибка осталась в журнале. Автоматические тесты парсера не являются проверкой GUI. Основной проверенный резерв этой сессии — отдельный реальный CLI/PTY, где оператором выступает агент на синтетике.

## Доказательства и пределы

browser-check.json/browser-signal.png — настоящий IAB и квитанция через1,577105с после приёма; includes queue/сеть/отрисовка. Это единичный замер, не p95/нагрузка/SLA. browser-after-restart.png — та же записанная реакция после настоящего kill/нового сервера. runtime.json — два реальных worker, три аварийных перезапуска, разрыв TCP до ответа на квитанцию, идемпотентный повтор. reserve.json — реальный процесс/PTY, принятые байты общего сигнала и синтетический SIGNAL без запуска браузера; не снимок Terminal и не настоящий врач. upgrade.json — обновление базы принятого cddc3ac с сохранением всех старых строк и обработкой прежде pending события. Копия/потери при разрушении диска/полное восстановление остаются S15, клиническая апробация S16. M05/T07 partial.

Дополнительный контроль окончательной версии: final-browser-measurement.json — 2,466392с от приёма нового HTTP-отчёта до browserreceipt, видимый сигнал безreload (browser-final-signal.png). Ранние1,577105с сохранены как отдельный первый прогон; ни одна цифра не является SLA или измерением реакции человека.
