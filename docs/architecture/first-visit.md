# Первый приём до диагноза — S17C

Протокол: `docs/clinical/first-visit-protocol.md`, версия `first-visit-s17b-v1`. Новый модуль `apps/compass/first_visits.py`, миграция `013_first_visits.sql`, экран `templates/first_visit.html`. Это технический сбор сведений в синтетическом локальном прототипе. Клиническая проверка B04 и короткая оценка B17 остаются открытыми.

## Вход и данные

Врач открывает карточку связанного пациента → «Первый приём без готового диагноза». Код заболевания, F41.1, прежнее назначение и анкета не требуются. Пациент продолжает вводить самоотчёты в прежнем кабинете; врачебная форма и её URL ему недоступны.

`GET /patients/<patient_id>/first-visits` показывает новую форму и сохранённые приёмы. `GET/POST /patients/<patient_id>/first-visits/new` начинает новую запись; адрес с конкретным `visit_id` возвращает последнюю сохранённую версию. Список снизу содержит снимки всех версий, включая первоначальные сведения.

Минимум: действующий врач/связь/синтетический пациент, дата наблюдения, тип первого/повторного приёма и жалобы либо явная отметка «сведения пока не собраны». Источник жалоб может быть пациентом, врачом или документом. Запись версии всегда содержит серверного автора, связь, момент внесения UTC, дату наблюдения по календарю Москвы и версию протокола.

V01 представлен отдельными полями возраста с прежней строгой проверкой `records.validate`. V02–V10/V12 представлены именованными полями: жалобы; течение/длительность; влияние на жизнь; предыдущая помощь; другие психические проявления; фактический приём препаратов/веществ/реакции; соматические обстоятельства; сведения безопасности; острые телесные жалобы; повторное обращение. Каждое поле хранит собственные состояние, текст, источник, основание и дату наблюдения. Пропущенная дата поля получает явно показанную общую дату наблюдения. Пустой статус — unknown, а не отрицание. Известные/противоречивые сведения требуют текста и основания; отрицание требует основания и пустого описания. Противоречивый текст должен содержать обе версии и источники; автоматической проверки достоверности свободного текста нет.

Документированные врачебные факты имеют отдельные текст и основание с документом/автором/датой, не извлекаются из жалоб и не создают код диагноза. `action_draft` — свободный проект действия, не исполняемая команда. Новых диагностических баллов/вопросников/порогов/экстренных правил здесь нет. V09/V10 — запись врача с видимым ограничением, не утверждённая процедура опроса.

## Версии и защита

Каждое сохранение добавляет строку `first_visit_versions`. Обновление/удаление запрещены триггерами. Черновик возобновляется, завершённая запись становится доступна для чтения; новые уточнения после завершения вводятся новым приёмом. Незавершённые сведения разрешены и при завершении записи; это не означает медицинскую достаточность данных.

`request_key` привязан хешем к автору/пациенту/адресу приёма. Тот же запрос возвращает сохранённый приём; изменённое тело с тем же ключом получает 409. `base_revision` проверяется под `BEGIN IMMEDIATE`: устаревшая вкладка получает 409 и сохраняет введённый текст на экране. Изменение данных/аудит атомарны. Доступ повторно проверяется в транзакции, включая активность врача и текущую связь; SQL дополнительно проверяет авторство/последовательность версий/пациента. Общий CSRF и запрет повторяющихся ключей формы сохраняются. Audit содержит событие и ID, без текста жалоб.

Старые таблицы/миграции/шесть исходных случаев не изменяются. Новый модуль не создаёт `clinical_entries`, `encounters`, `proposals`, `care_actions`, терапию, диагноз, направление, событие риска или государственную запись. Связанные факты возраста всех версий, включая черновики, добавлены в `ages.source_snapshot`: несовместимость блокирует взрослый допуск; новый снимок делает прежнюю сверку/предложенную DASS недействующими до повторной проверки. Противоречие не устраняется выбором последней удобной версии.

Новые версии приёма включены в `decisions.snapshot`. Подтверждение проекта, созданного до новых сведений, требует новой редакции/просмотра. Пустое новое хранилище не меняет снимки прежних проектов. Лечебное действие остаётся отдельным подтверждением врача на сервере.

## Сводка и инструмент

Экран раздельно показывает возраст, жалобы/источники, документированные факты, неизвестные/противоречивые сведения, проект действия, отдельные результаты инструмента и подтверждённые решения. Исторические подтверждения помечены временем/врачом/ID, актуальность плана проверяется в прежнем разделе решений.

V11 не дублирует анкету: экран читает существующую врачебную проекцию `assessments.history`, сохраняя точный идентификатор формы, дату, три отдельные суммы DASS-42 или отсутствие баллов при неполноте. Переход к предложению анкеты ведёт в прежний защищённый раздел: возраст проверяется там отдельно. Точный ресурс, подсчёт, исходные ответы и раздельные серии не изменены. DASS-21/PHQ2/GAD2 и новые клинические ветви не активируются.

## Решение по интерфейсу

Продолжена существующая рабочая композиция HAC: верхние ссылки на запись/сводку/историю, один столбец смысловых разделов, две колонки только для коротких метаданных. На узком экране — одна колонка. Поля V09/V10 и пробелы видны в общей сводке. Длинные ID переносятся внутри нового экрана. Системный шрифт, размеры и палитра прежние: ink #18352f, muted #52665f, accent #17634d, surface #fff, canvas #f3f6f5, warning #704508. Новых шрифтов/CDN/пакетов нет. Источник композиции — существующие экраны S13 и `interface-direction.md`; новые внешние референсы не требовались. Четыре шага и существенное упрощение отложены до назначенного S17E.

Проверки/снимки: `evidence/S17C/acceptance.md`, `browser-result.json`, `browser_check.cjs`, `apps/tests/test_first_visits.py`. Самопроверка агента не является апробацией, экспертным заключением или доказанной клинической безопасностью. Новые нагрузочные/мобильные/клинические замеры не выполнялись.

## S51 — накопительная запись, 26.10.2026

Новая форма note_schema=outpatient-v1; protocol physician-visit-s51-v2. Новые поля в JSON новых версий, без миграций старых строк. initial_values берёт пять постоянных разделов/возраст только из завершённых приёмов по клинической дате, затем времени записи. attach_provenance разрешает ссылки на точную завершённую версию того же пациента; не принимает клиентскую атрибуцию. Текущие поля и wellbeing не переносятся. age_observed_on отделяет дату прежнего возраста от даты приёма, ages.source_snapshot использует её для допуска анкет. Документы сохраняют новые поля через form_values; прежние medications/document/action поля при отсутствии в форме наследуются из точной базовой версии. Повторы/конфликты и транзакционные проверки прежние. Подробности — docs/clinical/visit-note-structure.md.
