# Допуск точных первоисточников DASS

S17J02B02, 21.10.2026. Допуск источника и достаточность клинического комплекта
проверяются раздельно. Этот срез добавляет происхождение, собственные факты и
доказательства ограничений; S17J02B03 ещё должен принять достаточные комплекты.

## Закреплённые идентичности

В retrieval_primary.py перечислены ровно шесть сочетаний ID, типа, конечного URL
и вида локатора: русский бланк DASS-42 Фаттахова–Горобец; английский шаблон
ключа; официальная страница перевода; FAQ; условия загрузки; публикация русской
валидации 2025 года с DOI10.17116/jnevro2025125051103. URL сверяется целиком.
Разрешения на любой URL того же домена, другой перевод или DASS-21 нет.

Новые типы instrument_form/key/provenance/guidance/terms и validation_study
сохраняют природу документа. Они не называются КР, ГРЛС или лекарственной
инструкцией. Старая проверка типов и исходных PDF остаётся прежней.

Точные SHA ответа, версии, время, размер, MIME, путь/SHA карточек и квитанции
закреплены в data/retrieval/primary-source-policy.json. Это доверенная локальная
политика администратора, а не ввод из вопроса. Регистрация пакета DASS42 сама
по себе не даёт содержательного допуска.

## Квитанция вместо копии произведения

original_storage=verified_primary_receipt разрешён только этим идентичностям
и только с reviewed_cards. path указывает на собственный JSON с URL, SHA
полученного ответа, временем, MIME, размером и указателем/SHA внешней проверки.
SHA источника не выдаётся за SHA локального файла: для квитанции есть отдельный
receipt_sha256. Отчёт исследователя обязан подтвердить точную запись и обычную
проверку TLS. Первое получение без проверки цепочки сертификата в этой сессии
не допущено; его заменило получение системным curl с проверкой сертификата.

Квитанция подтверждает проверенное получение, не наличие полного оригинала
на диске и не полнотекстовую лицензию. Для динамического HTML статьи SHA
относится к одному HTTP-ответу. Идентичность публикации дополнительно задают
точный URL, DOI и библиография; обновление требует новой проверки, а не
«подправленного» хеша или автоматической сетевой загрузки.

Русский бланк и ключ дополнительно связаны с SHA неизменённого ресурса
apps/compass/resources/dass42-ru-v1.json. Исследователь сверил инструкцию,
четыре варианта ответа, 42 пункта и распределение 42 номеров. Полная DASS-42
не получает множитель короткой DASS-21. Русский ключ сверяется по номерам с
английским шаблоном; отдельный официальный русский шаблон не утверждается.

## Представление и повторная проверка

В пакете и снимке нет исходных PDF/HTML, текста вопросов, полного ключа,
таблиц, OCR или эмбеддингов оригиналов. Только собственные факт-карточки.
Новые источники не допускают цитат. Для PDF указан физический номер страницы;
для HTML page=null и именованный раздел/номер вопроса, без выдуманной страницы.
Экспорт индекса по-прежнему содержит только paraphrase.

При каждом чтении eligible_sources повторно сверяет текущие пины, квитанцию,
отчёт, права, сроки и ресурс формы/ключа. Подмена или удаление записи,
неизвестные права, отзыв, просрочка, изменение отчёта или ресурса исключают
материал даже из старого снимка. Импорт воспроизводим, публикация атомарна,
старые снимки не перезаписываются. Сеть в импорте и вопросе не используется.

Официальное размещение и проверенный транспорт не дают клинического одобрения.
FAQ14+ не заменяет неизвестный возраст русской выборки; ограничения HAC18–120
остаются собственной политикой синтетического демо. Показания и безопасность
лекарства не подтверждаются источником DASS.

## Два происхождения доказательств

В COVERAGE-1 содержательная проверка schema_version=2 хранит для каждого аспекта
source_references и policy_references. Клиническому аспекту нужен допустимый
источник; проектному ограничению — отдельная запись HAC; смешанному — оба.
Пример структуры, не реальное клиническое заключение:

```json
{
  "source_references": [],
  "policy_references": [{"policy_id": "patient_no_computed_scores", "record_sha256": "<точный SHA>"}]
}
```

Назначение аспекта задаётся кодом и конкретной областью frozen-матрицы.
Одинаковое имя age_boundary в D12 относится к DASS, а в FU08 — к лекарству.
Последнее не может получить допуск от FAQ или собственной возрастной политики.
Для точной DASS/ключа, русской валидации, периода и прав требуются соответствующие
первичные ID. Карточка КР не заменяет исследование валидации. DASS-источник
нельзя использовать для лекарственного досье или иных клинических аспектов.

Проверки schema_version=1 продолжают читаться для чисто клинических аспектов,
но не могут скрыть проектную политику внутри источниковой ссылки. Старая
реальная coverage-evidence.json была пустой и не изменяется в этом срезе.
Полнота, клиническая истинность и поведение будущих отказов не присваиваются
структурной проверкой. G01–G09, 58 ячеек, 90 разделов и независимый врачебный
допуск сохраняются.
