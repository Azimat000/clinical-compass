# BE13 — проверяемые лекарственные ограничения

`backend_medication_safety.evaluate(candidate, patient)` — внутренний серверный
механизм, который BE14 может вызвать независимо от генератора. Новый HTTPмаршрут
не добавлен. Он не выбирает лечение и не подтверждает/не меняет действующий план.
Рабочая база015, сервис8000, очередь и интерфейс не переключаются.

## Вход

Только явные синтетические данные: `patient.mode=synthetic_only`, `synthetic=true`.
Реальный режим даётblock, ни одна проверка не создаёт клинический допуск.
`candidate`: точныйproduct_id(elicea/aleval/aviandr),form=film_coated_tablet,
strength_mgизкаталога,unit=mg,indication=adult_depressionдляпервыхдвухлибоadult_gad
дляАвиандра,daily_dose_mgчисло,times_per_dayцелое,phase=maintenance.
Строки «10мг», булевы числа, NaN/inf не принимаются. Никакого извлечения дозы,
препарата, отрицания аллергии или противопоказания из свободного текста нет.

Каждый факт пациента — `{value: ..., refs: [точные_ссылки]}`. Возраст — целое,
allergies — список кодов вещества/точной регистрации, medications — список
структурированных назначенных/фактически принимаемых/недавно отменённых препаратов.
`allergies_complete` и `medications_complete` требуют явногоtrue, а не пустоты.
Индивидуальные фактыrequired_facts — true/false; неизвестное/нетисточника/не тоттип
даётunknown. Точное значение различает беременность,ГВ,рискQT,гипонатриемии,
печёночные/почечныеусловия и др. Эти факты не являются анкетой для пациента.

Запись лекарства: ingredient — доверенный код вещества/проверенного класса, либо
product_id из каталога; state=current/recently_stopped; refsнепустые.
Конфликт кода вещества и точного препарата — unknown. Торговоеname не разбирается;
оба торговыхназвания одного вещества дают дублирование по коду вещества.
Без точного вещества неизвестное торговое название не считается безопасным.

Внешнему пользователю или модели нельзя передавать право придумыватьrefs,
утверждать полноту или synthetic=true. Вызывающий серверный компонент обязан
проверить врача/связь, синтетическое происхождение из базы, разрешитьrefs по
неизменяемому снимкуBE02, сохранить раздельно назначенное/фактическое/отменённое,
получить подтверждённые структурированные сведения, проверить свежесть контекста.
Прямого маршрута к функции нет. Подключение кBE14/BE15 ещё не выполнено и не
выдаётся за интеграцию конечного продукта. Текстовые историиS55/S56не конвертируются
автоматически в отрицательные клинические факты.

## Результат

Каждая проверка:code,state=pass/block/unknown,собственнаяпричина,input_refs,
точнаярегистрация,URLPDF/SHA256,раздел/страницы. Естьхешивхода/каталога/движка,
checked_at/expires_at.blockимеетприоритетнадunknown;unknownнадpass.
`verify`пересчитывает весь отчёт, отклоняет подмену факта/текста/источника/кода/
каталога и истёкшую/будущую квитанцию. Это проверка целостности отчёта, а не
утверждение лекарственной безопасности. Клинический допуск всегдаfalse.

Всегдаeligible=false/applied=false. Покрытиеограничений/взаимодействийpartial,
компонентыпрепаратаотдельноunknown. Доза — только поддерживаемая числоваяграница,
не оценкаминимальнойэффективности,начала/титрования/повышения/отмены/перехода.
Нельзя использоватьpassдозы как разрешение на произвольную схему.
Недавно отменённые лекарства требуют точного проверенного интервала; программа
не вычисляет его из текста/даты. Допустимые интервалыИМАОописаны вresearch,
но исполняемое правило перехода не заявлено. Покрытиеотсутствующего взаимодействия
unknown,а не отсутствие противопоказаний. Таблеткиделятсятолькоеслиподтверждено;
дляАлеваларисканеравнаравнойделимости. Количествомгнепревращаетсявмл/капли.
