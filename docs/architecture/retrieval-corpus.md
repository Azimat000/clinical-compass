# Локальный корпус: допуск и архив, S17J02

Версия протокола corpus-admission-1. Это отдельный административный инструмент
на прежней стандартной библиотеке Python. Он ещё не подключён к HTTP, поиску,
клиническим карточкам или БД пациентов. Результат исследования и фактический
допуск — evidence/S17J02/research.md и corpus-manifest.json.

Реестр `data/retrieval/source-registry.json` — доверенная проверенная политика
администратора. Его нельзя принимать из HTTP-запроса, текста документа или
ответа модели. Флаг approved сам по себе недостаточен: требуются официальный
тип/издатель/URL/версия/статус, точный SHA-256, доказательства популяции и
показаний, права local_store/local_index/display_excerpt, дата проверки и
review_due_at с часовым поясом, происхождение решения и связанная с точными
байтами проверка. Отчёт verification.evidence (один точный локальный путь)
сверяется с verification.evidence_sha256 при импорте и при каждой проверке
допуска; подмена, удаление или символическая ссылка блокируют источник.
Это контроль сохранности доказательства, а не автоматическая оценка законности.
Неизвестное не получает значения по умолчанию. Срок review_due
— собственный срок повторной проверки проекта, не срок действия КР или РУ.

Импорт разрешает только три явно перечисленных оригинала в LOCAL_ORIGINALS.
Сетевых обращений нет. URL служит ссылкой на источник, а не инструкцией скачать
файл. Клиническая рекомендация, пациентский листок и ОХЛП различаются; для
листка требуется домен ГРЛС, для КР — официальный рубрикатор/API. Производитель
не заменяет ГРЛС. Тип должен совпадать с разрешённым типом локального файла и
точной проверкой. SHA сверяется с полными исходными байтами, PDF проверяется
по заголовку; чтение и сверка страниц относятся к J03, а не к этой проверке.

Реестр редактируется явно после исследования. Для новой версии необходимо
сохранить старый оригинал и добавить новый точный разрешённый путь; текущая
узкая allowlist не является универсальным загрузчиком. Совпадающие ID, пути
или содержимое под двумя ID отвергаются. Произвольные пути/URL, символические
ссылки источников и подменённые байты не импортируются даже в архив.

`build_manifest` возвращает решения admitted/quarantined/archived и причины
по каждому источнику. Версия корпуса — SHA канонического manifest без самого
поля версии; manifest включает хеш полного реестра/решений и перечень байтов.
Дата запуска вынесена в отчёт операции, поэтому повтор в другой момент при
тех же действующих решениях даёт ту же версию, а не ещё одну копию. Оригиналы
копируются в каталог версии по SHA, старые каталоги не перезаписываются.
Повтор проверяет всё сохранённое содержимое. Повреждённый/частичный каталог
блокирует загрузку; автоматически чинить или подменять старую версию нельзя.

Команда вне процесса приложения:

```sh
.venv/bin/python tools/import_retrieval_corpus.py --destination /absolute/local/corpus
.venv/bin/python tools/import_retrieval_corpus.py --destination /absolute/local/archive --archive
```

`--at` предназначен для воспроизведения аудита с явным временем ISO и поясом.
Приложение не должно получать это время от пользователя: при реальной выдаче
нужны серверные часы. Нулевой допуск — NO_ADMITTED_SOURCE, а не успешный рабочий
корпус. Код возврата 0 команды означает только завершённую операцию с явным
отчётом, а не допуск источников, G02 или медицинскую безопасность.

`eligible_sources(snapshot_path, current_registry, server_time)` загружает
и проверяет SHA каждого файла/manifest, затем повторяет допуск по текущему
реестру и времени. Отзыв, потеря прав, новая редакция метаданных, удаление или
просрочка исключают источник сразу, даже при сохранённом старом снимке.
Изменившийся реестр не переписывает историю: необходим новый явный импорт.
Пустой действующий корпус даёт NO_ADMITTED_SOURCE; повреждённый снимок вызывает
CorpusError (будущий HTTP-адаптер обязан отобразить его в UNAVAILABLE).

Архив хранит только оригиналы с совпавшим SHA, включая карантин по правам или
просрочке. Архив никогда не возвращает admitted. Наличие архивной копии не
означает разрешения индексации или показа. Текущий локальный аудит не публикует
файлы и не создаёт новых лицензий; оригиналы уже сохранены в прежних пакетах.

В J03/J04/J06 потребуется использовать только результат повторной проверки,
закрепить точные фрагменты/вопросы реального допущенного корпуса до настройки,
проверить применимость, роли и защиту от изменения реестра между проверкой и
выдачей. Кэш не может обходить эту функцию. Атомарное переключение индекса,
конкурентная сборка, восстановление/резерв и эксплуатационные испытания остаются
J08. Этот подсрез не объявляет их выполненными. Семантика, генератор, новые
пакеты/модели/API и клинические действия не добавлены.
