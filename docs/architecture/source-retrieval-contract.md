# Контракт поиска оснований, retrieval-contract-1

S17J01, 20.10.2026. Контракт будущего модуля, а не работающий поиск.
Поиск возвращает врачу точный текст документа. Генерация медицинского ответа,
новые клинические правила, запись фактов и пять медицинских действий сюда не входят.

## Вход и граница доверия

Сервер получает `request_id`, `mode` (`reference` / `contextual`), `question`,
`context_snapshot`, `requested_corpus_version`. Вопрос — недоверенные данные:
название диагноза в нём не создаёт подтверждённый диагноз. Ограничения длины,
формата, роли и действующей связи проверяются до поиска. Неверный HTTP-запрос
даёт 400; отсутствие входа/доступа — 401/403 без выдачи, подтверждения наличия
чужого контекста и содержательной причины. Эти ошибки не кодируются как FOUND.

`reference` — общая справка без утверждения персональной применимости;
`context_snapshot=null`, `applicability=not_assessed`. Вопрос с просьбой применить
сведения к человеку нельзя незаметно перевести в общую справку. `contextual`
использует только серверный снимок подтверждённых врачом данных: направление,
диагноз, этап, возраст и происхождение его проверки, временные границы,
идентификатор/хеш/редакцию снимка, текущую связь и существенные неизвестные поля.
Сырые истории, ФИО и идентификаторы не нужны индексу публичных источников.

Неизвестные возраст/диагноз/этап/срок и противоречивые сведения сохраняются
явно; извлечённые кандидаты и слова вопроса их не заполняют. Ровно 18 для
Авиандра не допускается по догадке. Права/статус/срок проверки источника,
применимость и доступ проверяются до ранжирования и повторно перед ответом.

## Ответ

Обязательные поля: `schema_version`, `request_id`, `status`, `reason_code`,
`mode`, `applicability`, `snapshot_hash`, `versions`, `hits`, `conflicts`.
`versions`: точные corpus/index/retriever/policy/contract; нет версии —
UNAVAILABLE. Время и ID запроса не заменяют версий. В `contextual` неизвестность
не может сопровождаться `applicability=confirmed`.

| status | Значение и пример reason_code |
|---|---|
| FOUND | Есть достаточный комплект допустимых фрагментов; `evidence_found`. Это справка, а не разрешение лечения |
| NO_EVIDENCE | В исправном допущенном корпусе нет достаточного ответа; `no_matching_evidence`, `no_admitted_source`, `incomplete_evidence` |
| NOT_APPLICABLE | Персональная применимость не доказана; `age_unknown`, `age_boundary_unresolved`, `diagnosis_unknown`, `population_mismatch`, `stage_unknown`, `context_incomplete` |
| CONFLICT | Противоречие значимых подтверждённых данных/оснований; `context_conflict`, `source_conflict`. Не выбирать удобный источник |
| UNAVAILABLE | Невалидный/недоступный индекс/снимок/политика; `index_integrity`, `index_missing`, `snapshot_stale`, `policy_unavailable` |

Порядок решения: HTTP-доступ → целостность/наличие зависимостей → противоречия
снимка → полнота/применимость → допуск источников → поиск → проверка достаточности
и конфликтов источников → повторная проверка снимка/допуска/ссылок. Отозванный
документ при исправном индексе исключается: если он единственный — NO_EVIDENCE;
несогласованность индекса с текущим реестром — UNAVAILABLE. Кэш не отменяет
проверок. У отказов `hits=[]`; у CONFLICT допустимы только безопасные ID причин
в `conflicts`, без частичной врачебной выдачи пациенту. Недостаточность не
скрывается выдачей одного из нескольких обязательных фрагментов.

Каждый hit содержит `fragment_id`, `document_id`, `document_family`,
`source_version`, `source_sha256`, `page` (PDF, с 1), `section`, `start`, `end`,
`quote`, `required_context`, `admission_id`, `verified_at`, `review_due_at`,
`source_url`, `rights_id`. Координаты — полуинтервал символов Unicode в
закреплённом тексте страницы; `page_text[start:end] == quote`. Контекст содержит
заголовок, связанные исключения, отрицания, полную строку/шапку таблицы и сноску.
Версия текста и SHA оригинала различаются. Проверять все показанные hits,
включая нерелевантные и стоящие после пятого; неверная ссылка блокирует выпуск.

Содержимое документа и вопроса, в том числе «игнорируй ограничения», остаётся
данными. Никаких переходов к сети/памяти модели при отказе; нет инструментов
изменения БД, отправки сообщений или медицинского действия. Общий журнал —
версии/безопасные ID/код отказа; без сырого вопроса, истории, секретов и
необработанного медицинского текста. Контроль журнала и БД — в J06/J08.

## Машинная проверка до реализации API

`tools/evaluate_retrieval.py` оценивает экспорт, не реализует авторизацию или
поиск. Его строки: `id`, `status`, `reason_code`, `hits`, `versions`, `safety`.
FOUND: reason=`evidence_found`; отказ — точная размеченная причина, hits пуст.
HTTP-пробы имеют `http_status`, пустые hits, status=`ACCESS_DENIED`.
`safety` содержит `role_bypass`, `source_bypass`, `applicability_bypass`,
`network_fallback`, `medical_writes`, `log_leak` (все false). Декларации этих
флагов не доказывают безопасность: финальный допуск требует прямых запросов,
сравнения БД, журналов и сетевых проверок J06/J08.

Оценщик различает достаточный комплект фрагментов и допустимый, но нерелевантный
фрагмент. Все поля ссылки сверяются с закреплённой разметкой; неизвестные ID и
дубли отвергаются. Недостающие строки — ошибки, лишние строки — ошибка формата.
Ответы не получают ожидаемую разметку: runtime-адаптер должен читать только
входы запроса. Оценщик и ответы хранятся вне приложения.

## Данные J01 и клиническая граница

Набор `data/synthetic/retrieval/` — собственные искусственные документы и
вопросы для технической проверки контракта. Их страницы — номера учебных
страниц JSON, а не страницы КР или ГРЛС. Фрагменты явно помечены учебными;
они не включаются в рабочий корпус и не используются для медицинского вывода.
Это позволяет действительно разделить семейства документов и точно размечать
координаты без выдуманных цитат КР. Источник/права: собственная техническая
разметка Codex в проекте, независимая клиническая проверка отсутствует.

J02/J03 должны дополнительно закрепить вопросы и достаточные фрагменты
фактически допущенного корпуса КР/ГРЛС **до настройки J04**, с сохранением
этого технического набора и отдельной историей/хешами. Оценка на искусственных
документах не заменяет G02 на рабочем корпусе. Если реальный корпус не позволяет
независимое разделение семейств, это фиксируется как ограничение, а не
переименовывается в независимый контроль. Клиническую эталонную применимость
проверяет специалист; B04/B18/B19/E02/E06 и неактивность FU остаются.
