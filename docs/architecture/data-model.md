# Модель данных S04

Физическая схема: apps/compass/migrations/001_initial.sql. SQLite, внешние ключи включаются на каждом соединении. Даты/время событий — UTC ISO 8601 с микросекундами; birth_date — календарная дата. UUID для событий, текстовые идентификаторы предметных сущностей; код пациента уникален. В синтетическом seed D01–D06 сохранены как воспроизводимые ID. JSON — расширяемые снимки с проверкой json_valid, а не замена ключевых связей/состояний. Их предметные схемы и серверная проверка добавляются в срезах соответствующих функций.

## Сущности и отношения

| Группа | Таблицы | Сохраняемые сведения |
|---|---|---|
| Идентичность | users, sessions | Роль doctor/patient, будущий хеш пароля, блокировка, хеш токена/срок/отзыв; логин не реализован |
| Связь | patients, care_relationships | Возраст и его known/unknown/conflicting; один действующий ведущий врач, история связей, пользователь пациента |
| Медицинский контекст | encounters, observations | Запись/автор/происхождение, факты и единицы, время события и приёма, known/unknown/conflicting/denied, доказательства |
| Источники и определения | source_versions, catalog_versions | Версии/URL/хеш/дата проверки/популяция/права/валидация, определения scale/drug/rule/route/alert, возрастные границы, блокер и рецензент |
| Оценки | assessments, self_reports | Точная версия шкалы и подсчёта, ответы/полнота/балл, время заполнения/приёма, исходный самоотчёт, версия схемы/idempotency key |

| Терапия/маршрут | therapy_courses, referrals | Версия лекарства, схема, даты/обоснование off-label; категория mandatory/desirable, тяжесть/адресат, проект и подтверждённое действие |

| Критические признаки | alerts | Категории critical/therapy_safety/psychiatry_route, срочность, источник-правило, времена создания/просмотра/реакции, ответ |
| Общение | conversations, messages | Диалог внутри связи врач–пациент, отправитель/текст/время, ключ повтора |
| Приверженность | adherence_reports | Подтверждённое действие, плановое/фактическое время, taken/missed/unknown/conflicting, причина |
| Извлечение | documents, extraction_runs, extracted_facts | Формат/хеш/локальный storage_key, синтетичность, версия парсера, результат/ошибка, факт/цитата/позиция/уверенность/неизвестность |
| Согласия/следы | consents, audit_entries | Цель/версия/выдача/отзыв/ссылка на доказательство; автор/событие/сущность/время/метаданные |
| Доставка | outbox_events, event_receipts, deliveries | Событие/версия темы/снимок/попытки/следующий запуск/ошибка/dead; потребитель/квитанция; получатель/канал/доставка/подтверждение |
| Схема/поиск | schema_migrations, encounter_search | Версия SQL/контрольная сумма/дата; полнотекстовый индекс с insert/update/delete-триггерами |

## Инварианты и расширение

- unknown → значение SQL NULL, не false/0; отрицание denied отдельно от отсутствия. D06.age_reports сохраняется снимком, age_status=conflicting. Отсутствие строк adherence — отсутствие данных, не missed.
- Неполная/неизвестная анкета не имеет балла. assessment ссылается на конкретную версию; сравнение разных переводов/версий не допускается автоматически. Ограничения соответствия kind=scale и полноты ответов добавляются предметным сервисом S07, сейчас API оценок нет.
- В catalog_versions статус reviewed требует рецензента/даты/возрастного основания, но не означает активацию: движка правил здесь нет. Предметный сервис обязан проверить актуальность источника/права/научное основание/возраст/неизвестности до исполнения в S07–S09. Одной строки reviewed недостаточно.
- В care_actions нельзя сослаться на отсутствующее/отклонённое подтверждение. Триггер подтверждения проверяет роль/активность врача, текущую связь, версию и неотозванный проект. Подтверждение неизменяемо; изменение требует нового проекта. Контроль авторства HTTP-запроса, согласованности всех patient_id, состояния связи на время действия, kind определений и off-label-обоснования — следующие предметные сервисы, не скрытые готовые гарантии S04.
- Версии источников/правил не перезаписывать при обновлении: создавать новые ID; старые оценки и проекты сохраняют свои ссылки. Автоматическое запрещение UPDATE каталогов будет в сервисе активации; сейчас каталоги пусты и UI только чтение.
- База имеет 001_initial; мигратор отклоняет изменённые/удалённые применённые SQL-файлы. Обновление — 002_*.sql в транзакции. При ошибке DDL откатывается; FTS проверяется созданием таблицы. Полная резервная копия — SQLite backup при остановленном worker/сервере или специальная проверенная процедура S15, не простое копирование работающего файла.

Тесты каркаса подтверждают связи, ограничения неизвестного/анкеты/подтверждения, идемпотентность seed, поиск/обновление индекса, откат миграции и сохранение после перезапуска. Они не подтверждают клиническую полноту рабочих процессов до их реализации.
