# BE14: внутренняя проверка кандидатов — работа не завершена

Версия therapy-inspection-wip-v1. BE14 не принят; положительная генерация
лечения, очередь/HTTP и применение не реализованы этим модулем.

backend_therapy.inspect(db,user,patient_id,candidates) — внутренний read-only
вызов разработки. Только текущий связанный врач и вымышленные истории.
Авторизация проверяется раньше формата кандидатов. Чтения выполняются в одном
SQLite-снимке; внешний transactionне завершается. Модуль не принимает patient,
факты/refs/утверждения об отсутствии противопоказаний от модели или клиента.

Неизменяемый снимок строится существующим backend_analyses.capture(plan).
BE12проверяет сроки/отзыв источников, критерии/свежесть диагноза и риски.
Нет свежего решения врача, риск/неполные критерии — отдельные preconditions.
Собственный код сверяется точно сF32/F33/F41.1. Нет сопоставления по рассказу.
Из снимка пока проецируется только точный непротиворечивый возраст; остальные
лекарственные факты остаются неизвестными. Даже существующая валидная ссылка
на строку сама по себе не доказывает смысл аллергии/вещества/переносимости.

Каждый структурированный кандидат независимо проверяется BE13; квитанция
пересчитывается. Дополнительно проверяются соответствие показания диагнозу и
фаза. initiation/change/stopне переименовываются maintenanceради прохода
проверки. Дозы/единицы/формы проверяет отдельный движок; дозыизтекстовнеизвлекаются.
Для каждогоunknownесть причина/вопрос и при наличии точный источник/локатор.
Начало/продолжение/изменение/отмена остаются различимыми, но готовые схемы
перехода/снижения не выдумываются.

candidate_reviews — отвергнутые либо требующие уточнения данные аудита разработки;
числовое поле candidate не является назначением. dose_sourceуказывает только
основание числовой проверки; regimen_basisnull. recommendationsпусто,
recommendable/applied/patient_published/clinical_releasefalse. Нового пользовательского
экрана, HTTPмаршрута, фонового генератора, записи в план/медикаменты нет.
Модуль не подключён к работающим процессам8000/workerи не добавлен в API.

Это ограниченный результат WIP, недостаточный для BE14-A01–A03. BE13 имеет
безусловныеunknownкомпонентов/покрытия/регистрации. Даже оптимистичная авторская
структура не даёт ни одного полногоpass. Генератор не может объявить неизвестное
разрешённым. Нужно дополнить проверенный каталог/механизм и сверку кодированных
фактов, затем реализовать генерацию через прежний модельный адаптер/очередь,
повторную проверку перед публикацией и реальную оценку положительных и опасных
случаев. Все первоначальные критерии остаются в BE14, новый подготовительный
срез не создан. Требуемая клиническая приёмка отдельна вBE19.

Источники/права/границы — evidence/BE14/research.md; их наблюдение не продлевает
срок допускаBE03. Восстановление — исправляющий коммит кода; рабочая база и
платёжный ledgerне сбрасываются. Новых миграций/пакетов/внешних вызовов нет.
