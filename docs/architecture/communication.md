# Коммуникация и выполнение плана S11

Локальный синтетический режим прежнего Flask/SQLite. Новых зависимостей, внешних каналов и клинических алгоритмов нет. Раздел `/patients/<id>/communication` доступен из карточки обоим участникам действующей связи. Внешнее развёртывание/шифрование/реальная апробация здесь не принимаются.

## Сообщения

Сервер заново проверяет активные учётные записи, пациента и действующую связь внутри транзакции. Адресата выбирает сервер: пациент либо ведущий врач. conversation закреплён за исходной связью; новая связь не получает прежнюю переписку автоматически. Получение чужого сообщения, запись в чужую карточку и изменение чужих отметок запрещены. POST требует прежнюю сессию/CSRF; HTML экранирует тексты. GET/HEAD не создают квитанций.

Сохранение сообщения, контекста и события аудита атомарно. 32-значный случайный hex-ключ обеспечивает повтор с тем же содержимым; другое содержимое/автор/контекст/связь по тому же ключу дают 409. «Сохранено» = серверная запись. «Получено» = явная отметка адресата. «Прочитано» = отдельная явная отметка адресата, одновременно ставит получение. Это утверждения пользователя, не автоматический замер экрана. Повторные отметки не меняют исходные даты.

JavaScript отправляет форму, сохраняет её содержимое/ключ при сетевой неопределённости и предлагает повтор. На время запроса поля заблокированы, двойной клик не отправляет новую форму. Данные не кладутся в browser storage; при закрытии/обновлении страницы неотправленный текст теряется. Без JS обычный POST работает; после неизвестного результата нужно повторить ту же форму, а не создавать заново. Новые сообщения видны после обновления страницы. Нет push/email/SMS и обещания постоянного наблюдения.

Сообщение может ссылаться на запись самоотчёта/визита того же пациента и пункт той же связи. Ссылка на запись ведёт к её НЯ/самочувствию, ссылки разделов возвращают к общей динамике. Текст не становится клиническим фактом и не запускает A02-v2: для медицинских сведений используется отдельный самоотчёт. Клинические сигналы S09/S10 сохраняют свой отдельный путь. Сообщение не меняет лечение.

## Пункты и знаменатель

Врач вручную выделяет одно выполнение из текущего подтверждённого решения therapy_start/change/plan_change, задаёт описание и точное время с часовым поясом, отдельно подтверждает соответствие. Сервер не выводит дозы/частоту из свободного текста и не разрешает пациенту создавать расписание. Отклонённый/неподтверждённый проект, неактуальный action, therapy_stop/referral не дают нового пункта. Все времена сохраняются UTC. Допустима ретроспективная регистрация синтетического пункта с явной датой создания: журнал не доказывает заранее согласованное расписание.

После срока врач либо пациент добавляет taken/missed/unknown/conflicting; для missed/conflicting обязательна причина. Сохраняются автор, время, ключ и вся история. Последняя явно введённая отметка — текущий сообщённый исход, а не объективный факт; уточнение создаёт новую строку. Выполнение будущего пункта не записывается заранее. Новое решение исключает старые пункты со сроком от первого последующего подтверждения; уже наступившие до смены остаются историей. Промежуточная отмена не исчезает после ещё одной смены плана.

Числитель = taken, известный знаменатель = taken + missed среди наступивших и не исключённых пунктов. unknown (включая отсутствие отметки), conflicting, будущие и исключённые показаны отдельно. При известном знаменателе 0 процента нет. Полнота исходов видна как known из due; процент не объявляется приверженностью всей терапии и не имеет медицинских порогов. Источники результата/причины доступны обеим ролям. Модель не выдаёт отсутствие ответа за пропуск.

Новые сообщения/пункты/отметки включаются в снимок решения: старый неподтверждённый проект требует повторного рассмотрения. При пустых новых таблицах старый снимок остаётся совместимым. Таблицы messages/conversations используются из 001; migration010 добавляет message_context/message_receipts/adherence_tasks/adherence_entries, исходные SQL не меняются. Исходная adherence_reports сохраняется для совместимости, не получает вымышленных записей.
