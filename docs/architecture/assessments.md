# S07: измерение симптомов и раздельные представления

assessments.py использует единственную зафиксированную DASS-42 из resources/dass42-ru-v1.json. Продукт не скачивает источники и не обращается к внешним API. Сохранены точные текст/период/ответы/ключ/популяция/права/URL/хеш PDF и проектная версия. Источник проверен исследователем, текст перенесён без изменения; отдельное клиническое одобрение не имитируется.

## Выпуск и хранение

004_assessments добавляет assessment_form_releases, assessment_requests, assessment_results и ограничения неизменяемости. 001–003 не меняются. create_app идемпотентно устанавливает источник/описание и выпуск synthetic_demo; при несовпадении опубликованной версии не переписывает старые определения. Выпущенные текст/ключ/источник защищены от изменения; отдельная смена статуса retired/актуальности/прав позволяет отключить форму.

source_versions содержит verified для прав/русской валидации конкретного источника. catalog_versions.status=inactive, reviewed_by/at=NULL: клинический движок не утверждён. assessment_form_releases.scope=synthetic_demo допускает только измерение на синтетических пациентах. Это разделение источникового выпуска и клинической активации без фиктивной подписи демо-врача. Для терапии/маршрутов/оценки риска этот выпуск не действует.

Запрос фиксирует врача, пациента, конкретную relationship, форму, возраст/дату/источник/снимок, серверные время/срок и ключ повтора. Результат связывает core assessments с запросом, автором, датой наблюдения, временем приёма и scores_json. assessments.score всегда NULL — общего итога DASS нет. При incomplete scores_json=NULL; ответы сохраняются.

Новый текст/источник/ключ требует новой версии. История группируется по scale_version_id/scoring_version/source_sha256; разные версии не смешиваются. Источник/права/версия проверяются перед предложением и приёмом. Нет множителя DASS-21/порогов/категорий/интерпретации.

## Доступ и приём

POST /patients/id/assessment-requests — только ведущий врач, CSRF, synthetic=1, сверенный возраст 18–120 и источник. Сервер сравнивает профиль/записи; unknown не совершеннолетие, последнее противоречие блокирует. Новая явная сверенная запись не удаляет историю. Предложение только на текущий день, максимум 24 часа.

GET/POST /assessments/request_id — связанный пациент/ведущий врач. Пациент не создаёт предложение себе и не подменяет версию/пациента/возраст. Перед записью связь/срок/возраст/источник проверяются под write-транзакцией. Новая связь не наследует открытый запрос. Собственная квитанция завершённой анкеты остаётся доступна пациенту после окончания связи без возможности менять ответ.

Только 42 известных поля с кодом 0–3 либо пропуском. Дубли полей/лишний номер/неверный диапазон/дробь отвергаются. Ответы/суммы/метаданные/аудит сохраняются одной транзакцией. Повтор того же запроса/содержания возвращает прежнюю запись, изменённое тело отвергается. Повтор в действующем окне предложения; исправление — новая анкета.

## Проекции

Врачу доступны ответы/три суммы либо неполнота, автор/период/даты/возрастной источник/версии/хеш/ссылка и графики/таблица. Пустой ответ не ноль; неполная анкета не даёт точки. График — наблюдения по порядку с датами в таблице, без выдуманной непрерывной кривой. До 30 точек в графике, записи не удаляются.

Пациентский API использует отдельный SELECT только request_id/requested_at/recorded_at/form_version_id. Ответы, суммы, полнота и интерпретация не выдаются. Завершённая анкета использует отдельный receipt-шаблон. Врачебные данные не рендерятся в скрытых элементах пациентской страницы; аудит не содержит ответов/сумм.

records.wellbeing_trend — отдельный пациентский дневник: 30 последних самоотчётов, категории лучше/без изменений/хуже/не указано, точные даты/источники в таблице. Категории не накапливаются и не становятся тяжестью. Визиты врача не переименовываются в пациентские самоотчёты.

## Проверки и границы

Тесты: ручные векторы/42 позиции пропуска, недопустимые ответы/версии, возраст/новые противоречия/сведения, роли/CSRF/срок/смена связи, отсутствие пациентских результатов, атомарность/повтор/неизменяемость, XSS, миграция S06. Process smoke запускает два настоящих WSGI-процесса и проверяет полную/неполную анкеты и раздельные API после перезапуска.

Это технические доказательства, не внешняя клиническая апробация. Нет диагнозов/тяжести/назначений/направлений/алертов из DASS. B04/S16/M09 и условия реального применения остаются отдельно.

## S34 — каталог и динамика (23.10.2026)

Разделы S07 выше описывают исходную единственную DASS и сохраняют историю. Теперь `definition(form_id)`/`definitions()` загружают три точных выпуска: прежнюю DASS-42, GAD-7 и PHQ-9 Золотаревой2023 (`resources/*-ru-v1.json`). DASS по умолчанию сохранена для совместимости. Новые формы: 7/9 пунктов, четыре значения0–3, отдельная сумма0–21/0–27, возраст18–90 по русской валидационной выборке, собственные source/code/hash/scoring_version. При любом пропуске scores=NULL. Ни диагнозов, ни категорий тяжести. Точные источники, популяция, права и отложенные кандидаты — evidence/S34/research.md. Схема БД не менялась; новые записи источников/каталога/выпуска добавляются идемпотентно, старые не переписываются.

Уточнение пользователя: обязательный интервал нельзя выдумывать по окну воспоминания. У всех трёх `mandatory_min_interval_days=null`: ранний повтор разрешён. Выбор врача показывает период и последнюю отправку. Дубли одного действующего приглашения блокируются сервером внутри BEGIN IMMEDIATE; повтор с тем же ключом безопасен. Новая возрастная информация делает старое приглашение непригодным и не мешает предложить свежее после сверки. Истёкшее приглашение без ответа не запускает интервала. Для будущего инструмента с обязательным интервалом общий движок проверяет историю пациента по code через все версии/врачей, на предложении и приёме; в отказе причина и точная московская дата. В текущем выпуске такое ограничение не активировано.

`assessment_charts.html` общий для карточки и сводки за выбранный период: отдельные серии exact-version/scoring/hash, DASS — три отдельных графика, PHQ/GAD — по одному. Линейная календарная ось, фиксированный диапазон шкалы, точки измерений, прямые отрезки без сглаживания; неполный ответ прерывает линию и не становится нулём. Последние30 анкет на графике, вся история в таблице/исходных ответах. Последний доступный результат и изменение между двумя полными измерениями со своими датами; это изменение балла, не вывод об эффективности лечения. Одинаковая календарная дата может давать наложение точек; точное время приёма доступно в исходных ответах. Исходные ответы доступны врачу по ссылке, значения — также таблицей без JS. На телефоне три подшкалы DASS становятся вертикальным списком. Никаких внешних библиотек/запросов.

Пациент получает название/срок именно выбранной анкеты, заполняет её точные вопросы и получает квитанцию без сумм/ответов/расшифровки; отдельный SELECT API по-прежнему имеет ровно4 безопасных поля. Врачебный приём больше не подписывает PHQ/GAD как DASS и выводит только присутствующие подшкалы. Общая возрастная/ролевая/связевая/CSRF/неизменяемая защита сохранена. Новые источники не включают клинические рекомендации или реальные медицинские действия.

## S35 — авторское дополнение существующих историй

Контрольные суммы/согласование — evidence/S35/consistency.md. Два заполнения P108неполные. Обычные источники/тексты/ключи/интервалы и интерфейс S34не меняются.

Разовая утилита `tools/seed_roster_questionnaires.py` по умолчанию делает только read-only preview. `--apply --backup <новый приватный путь>` добавляет три связанные строки каждой анкеты и реальный журнал происхождения одной транзакцией. Она принимает только узнаваемый S30состав/источник, сверяет личности, возраст, прежние неизменяемые приёмы/DASS и связи/версии/допуск. Исторический снимок возраста берётся из прежнего запроса DASSтого же дня: текущие будущие записи не подставляются в прошлую сверку, глобальные часы не подменяются. Смоделированные request/recorded_atотделены от настоящего actual_imported_atв audit. Это намеренно **синтетический импорт**, не доказательство выполнения пациентами форм в прошлом и не обычный клинический POSTзадним числом.

Детерминированные идентификаторы дают повтор0добавлений. Несовпадающий ранее импортированный результат/частичная коллизия/изменившееся происхождение отвергаются. Другой уже существующий ответ на ту же дату сохраняется и явно пропускается, источник/права должны оставаться доступными. Изменение опорного исходного DASSпункта21требует явной повторной авторской проверки; нет машинного перевода этого ответа вPHQ. Старые строки, аккаунты, решения, расписания, самоотчёты и источники не обновляются/не удаляются; новых рекомендаций/алертов/сообщений нет. При запуске сервиса утилита автоматически не вызывается.
