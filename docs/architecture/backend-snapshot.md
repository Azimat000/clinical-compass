# BE02 — единая история и точные исходные версии

Версия адаптеров: `patient-history-v2`. Только сервер и синтетический контур;
модель не подключена, клинический выпуск заблокирован. Код — backend_snapshot.py,
интеграция — backend_analyses.capture/inputs/advance, договор — backend-api.json.

## Состав и авторитет данных

Сырые строки существующего decisions.snapshot сохраняются без изменения.
Дополнительно захватываются полные строки assessment_requests, proposals,
doctor_confirmations и decision_drafts только этого пациента. Это вход анализа;
существующий механизм создания/подтверждения лечебного плана не меняется.

| Источник | Исходные таблицы | Единое представление |
|---|---|---|
| Анкеты | assessments + assessment_results + assessment_requests; catalog/source/releases в сыром снимке | Все ответы/пропуски, суммы либо null, версия формы/подсчёта, полнота, фактический автор ответа, две даты. Назначивший врач не выдаётся за ответившего |
| Самочувствие | clinical_entries.kind=self_report + связанные self_reports/observations; отдельно прежние несвязанные self_reports | Текст, явные статусы/отрицания/неизвестное/конфликт, возраст, динамика, medication_feedback/safety при наличии |
| Анамнез | Все first_visit_versions: history/life_history/family_history/somatic/allergies; прежние observations тех же кодов | Отдельное представление cumulative_history, исходная дата поля, источник, основание и carried_from; та же версия, что в приёме |
| Приёмы | clinical_entries.kind=visit, несвязанные encounters, все first_visit_versions | Полные поля/тексты, возраст, динамика врача, документальные сведения и прежние заметки о действии; черновик/завершено, версия и supersedes_ref |
| Лекарства/план | proposals + drafts + confirmations + actions; therapy_courses; medication_marks | Назначенное/отклонённое/неподтверждённое отдельно от фактического приёма; все исправления отметок, автор, дата дозы, время внесения, actual_quarters |

Связанные clinical_entries/self_reports/encounters/observations — один эпизод с
related_refs. Разные записи с одинаковым текстом остаются раздельными.
Представления anamnesis и visits имеют один ref: ключ элемента `(ref, category)`.
Это разделы одной записи, а не второй приём. Прочие старые таблицы, переписка и
загрузки остаются в сыром снимке; автоматического извлечения из них здесь нет.

## Смысл полей и пределы

- event_at — сохранённая дата/время события; recorded_at — время внесения.
  Поздняя запись не переносится на день внесения. Календарная дата не превращается
  в вымышленное время UTC. Неизвестные автор/время прежней строки — null.
- temporal_scope сравнивает день события с московским днём снимка: historical,
  on_snapshot_day, future, unknown. context=current — текущие жалобы на дату
  конкретной записи, cumulative_history — анамнез. Это не актуальность сегодня.
- current_revision — последняя версия конкретной записи/отметки. Черновик остаётся
  state=draft; последняя версия не равна медицинской истине или одобрению врача.
- active_plan_ref — последнее применённое действие по прежнему порядку version.
  active_medication_plan_ref — последнее одобренное явное изменение состава,
  согласованное с medications.approved. Обычное изменение плана не стирает состав;
  неподтверждённый проект не применяется.
- prescribed_only отдельно от reported_intake. actual_quarters=null — неизвестно,
  0 — сообщён нулевой приём; единица — четверть таблетки прежней формы, не мг.
  Отсутствие отметки не превращается в пропуск.
- known/unknown/denied/conflicting переносятся из источника. Пустое отрицание
  сохраняет статус denied. Свободный текст не разбирается на отрицания/диагнозы:
  это BE05. Пустое поле не равно отсутствию риска.
- issues: explicit_conflict:code или same_day_disagreement:code для разных
  структурированных значений одного кода в один день. Старые версии и повторный
  вид анамнеза не голосуют дважды. Это различие записей, не клиническая оценка;
  смысловое сопоставление ещё BE05/08.

Разные анкеты/их суммы и произвольные тексты summary/narrative не объявляются
противоречием только из-за различия значений. Если новая история превышает
предел снимка либо зависимость источников недоступна, GET анализа возвращает
stale: неподтверждённая свежесть не оставляет прежний результат актуальным.

## Неизменяемость, ссылка, полнота

`s2_` + SHA-256 от `[table, primary_key, full_frozen_row]` обозначает точную
версию источника. sources хранит таблицу/ключ/значение ключа и SHA-256 строки.
Resolver сверяет отпечаток и открывает сохранённую строку, не актуальную строку
базы. Поле указывает source_ref + path: например,
`/payload_json/fields/complaints/text`. JSON-столбцы декодируются при проходе пути.
value совпадает с исходным значением, включая переводы строк; текстовый фрагмент
здесь — полное поле. Суммы анкеты ссылаются на assessment_results, не assessments.

Ссылка ограничена пациентом и конкретным запуском. Новых таблиц/миграций нет,
используется append-only analysis_input_snapshots BE01. Защищённые строки нельзя
изменять/удалять. Допустимое удаление несвязанного прежнего архива или отзыв
источника не меняет старый снимок; прежний анализ становится stale.

complete=true — адаптеры перенесли все доступные записи, а не обследование полно.
missing_categories перечисляет пустые входы. counts/entry_count учитывают все
версии и представления. Порядок: event_at, recorded_at, ref, category, неизвестная
дата сначала. Страница содержит до50элементов одного snapshot_id; новые сведения
не сдвигают старые страницы. LIMIT/скрытой обрезки нет. Общий размер канонического
UTF-8 снимка ≤4 194 304байт; больше → 409 snapshot_too_large с атомарным отказом
создания анализа. Страницы не обходят этот предел. Готовность для больших входов
за этим пределом не заявлена.

SHA-256 снимка включает входы, источники, SHA API/матрицы, день/связь и версию
адаптера. Текущего времени вызова/логов входа/ID анализа в нём нет: одинаковые
входы в один день дают одинаковый отпечаток. Новый факт/исправление/отзыв/план/
день делает старое устаревшим. Это консервативное сравнение BE01, ещё не очередь
BE06. Захват/свежесть/чтение частей выполняются в согласованной транзакции SQLite.

## HTTP и совместимость

Потребитель — будущий врачебный клиент/серверный исполнитель, владелец договора —
сервер HAC. Выбран существующий JSON HTTP для чтения страниц и исходной версии;
GraphQL/события не нужны для этих чтений. Схемы HistoryPage/HistoryEntry/
HistoryField/HistorySource опубликованы в backend-api.json.

`GET /api/v1/patients/{patient_id}/analyses/{run_id}/inputs?page=1` — HistoryPage.
page — положительное целое ≤999999999, по умолчанию1; вне реальных страниц,
повтор или неизвестный параметр → 400 invalid_page.

`GET /api/v1/patients/{patient_id}/analyses/{run_id}/inputs/{reference}` —
HistorySource с исходной строкой/отпечатком. Оба адреса поддерживают HEAD,
действующую сессию врача той же связи, no-store, не записывают данные.
Без сессии401, пациент403, чужая/заменённая связь/запуск/ссылка404. Старый снимок
BE01 без patient_history →409 snapshot_version_unavailable, без дописывания
задним числом. Ошибка отпечатка →409 snapshot_integrity. Общие500/503 и
редактирование ошибок — API BE01. У исходной версии игнорируются query-параметры,
они не выбирают другую строку. Эти запросы не применяют лечение и не публикуют
сведения пациенту.

Analysis/API1.0 и прежние evidence_refs `table:id`/`profile:id` сохранены. Новые
точные refs тоже проверяются advance. Старые результаты доступны для истории,
но изменение SHA API/формата входов намеренно делает их stale, нужен новый запуск.
Прежние строгие декодеры Analysis и новые схемы проверены тестами. Внешних
известных потребителей/SDK нет; сторонние генераторы не проверялись.

Сайт8000/worker/база/доступы не обновлялись. Для будущего развёртывания нужны
согласованная копия0600 и штатная migration016 BE01. Откат — прежний код и
согласованная копия при остановленных процессах; историю вручную не чистить.
Проверки — test_backend_snapshot.py, test_backend_contracts.py, make check и
verify_snapshot.py на копии всех десяти историй. Реальные результаты:
evidence/BE02/acceptance.md и memory/sessions/BE02.md. Клинические источники,
права/сроки/правила и возрастные ограничения анкет не менялись.
