# Справка и оценка терапии врачом — S08

F02 допускает справочную информацию о вариантах терапии. Продукт использует этот путь: краткие карточки фармакотерапии, психотерапии, психообразования/наблюдения и ограниченную справку Авиандра с первоисточниками. Никакого автоматического назначения из диагноза/шкалы нет. Новый файл therapy-reference-v2.json не перезаписывает v1; источник/раздел/РУ/срок/дата проверки сохранены. Листок ГРЛС называется пациентским листком, не ОХЛП. Лекарственных сведений о других препаратах нет.

При создании проекта назначения/изменения/отмены врач заполняет восемь областей: показание, возраст, противопоказания, органы, взаимодействия, особые группы, режим, НЯ/наблюдение. В каждой — состояние и обязательное пояснение (данные случая/источник/дата/оценка). По умолчанию unknown. Состояния concern/unknown/conflicting различаются; пустое пояснение не принимается. Даже неприменимость должна быть обоснована. Для направления/изменения плана эта лекарственная форма не требуется; отдельное подтверждение врача требуется всем пяти действиям.

Результат рассмотрения Авиандра: not_selected, insufficient_data либо individual_review («Сведения сверены; дальнейшее решение принимает врач»). Последний вариант запрещён сервером при любом unknown/conflicting/concern. Список нерешённых областей/рисков сохраняется и показывается врачу. Это проверка согласованности записанной врачом формы, не машинная проверка пациентского диагноза/СКФ/возраста/лекарств: приложение не анализирует свободный текст и не устанавливает пригодность препарата. eligibility_established и automatic_recommendation всегда false. «Проверено врачом» — утверждение автора проекта в синтетическом демо, не внешняя клиническая экспертиза и не фиктивный reviewed_by каталога.

При неполных сведениях врач может подтвердить вручную записанный план, например собрать недостающие данные/обсудить другие варианты. Подтверждение такого плана не превращает unknown в отсутствие риска и не создаёт лекарственный курс. Вне инструкции система сама ничего не предлагает; ручное индивидуальное решение, включая отступление от инструкции, остаётся ответственностью врача, с текстом/основанием/неопределённостью и отдельным подтверждением. Свободный текст не проверен на соответствие инструкции и не выдаётся за проверенную лекарственную рекомендацию.

Оценка хранится внутри неизменяемого payload проекта, вместе с полной версией справки, автором, снимком пациентских сведений и связью. Новый визит/НЯ/сверка возраста/курс/источник/день/план делает старый неподтверждённый проект непригодным для принятия; требуется новая версия. Правила S08A/S08B/транзакция/идемпотентность сохраняются. Старое подтверждение остаётся историческим фактом, а повтор запроса — его квитанцией, не новым применением. Пациент получает только подтверждённый текст плана; внутренняя восьмиобластная оценка и снимок выдаются только врачу. Историческая оценка отображается с сохранёнными названиями/версией, не текущими подписями.

Активные R01–R19/A01–A05 не включены. Программный контроль согласованности формы не следует называть клиническим оценщиком. B04 остаётся для автоматических клинических условий, тяжести/причинности/срочности, полной совместимости и реальной апробации. S09 добавляет маршрутизацию/критические признаки отдельно; S11 — управление курсами и приверженность. Все требования/подпункты сохраняются для дальнейшей проверки.

Проверки: test_therapy.py (неизвестность/отказ/полная врачебная форма без допуска/24 сочетания ограничений/версия/повтор/экранирование/проекция/6 случаев), test_decisions.py, полный make check, настоящий двухпроцессный smoke_restart с сохранённой неполной оценкой в обоих кабинетах. verify_upgrade.py создаёт базу настоящим принятым кодом S08B, проверяет сохранность всех прежних строк/источника v1/подтверждения и отказ старому неподтверждённому проекту после перехода на v2. Это технические синтетические проверки, не клиническая апробация.
