# Архитектура каркаса S04

18.10.2026. Доступно локальное синтетическое демо: адаптивная страница, шесть карточек из S03, полнотекстовый поиск/фильтр, миграция и устойчивая очередь технических событий. Вход и разделение доступа — S05; запись самоотчётов — S06. Медицинских вычислений, активных шкал/правил и внешних уведомлений в S04 нет.

## Компоненты и границы

| Компонент | Файл | Ответственность |
|---|---|---|
| Интерфейс | apps/compass/templates, static | Серверный HTML, CSS, мобильная компоновка; внешние шрифты/скрипты отсутствуют |
| HTTP | apps/compass/web.py | Фабрика Flask, только GET, соединение на запрос, закрытие соединения, безопасный вывод текста |
| Доступ к данным | apps/compass/repository.py | Параметризованные запросы, поиск, ограниченная выборка, идемпотентное заполнение синтетикой |
| База/миграции | apps/compass/db.py, migrations | Явные транзакции, внешние ключи, версии и контрольные суммы схемы |
| События | apps/compass/events.py | Событие записывается вместе с изменением данных; обработка, повтор, очередь ошибок |
| Запуск | apps/compass/__main__.py | migrate, seed-demo, status, serve, worker; Waitress без debug/reloader |

Путь: браузер → Waitress → Flask → repository → SQLite. Отдельный worker читает таблицу outbox_events той же базы. Создание пациента, снимка профиля, записи, аудита и события выполняется в одной транзакции: либо сохраняется всё, либо ничего. После остановки процесса очередь остаётся в файле базы.

Обработчик S04 сохраняет только техническую квитанцию demo_receipt_v1. Это не алерт врачу, не доставка сообщения и не клиническая реакция. Неизвестная тема не признаётся обработанной: повтор через 2/4/8/16 секунд, после пятой ошибки статус dead. Частично выполненный обработчик откатывается до savepoint; событие и локальная квитанция фиксируются атомарно. Повторная обработка уже processed не выполняется. Удержание write-lock во время короткого локального обработчика допустимо здесь; сетевые действия внутри него запрещены архитектурой будущей доставки. Для S10/S11 нужен отдельный механизм доставки с идемпотентностью получателя, квитанциями и восстановлением; exactly-once для внешней сети не заявлено.

## Рост и расширение

SQLite — сознательный выбор для одного локального демо. Один писатель, короткие транзакции BEGIN IMMEDIATE, timeout 10 секунд. Использован rollback journal DELETE и synchronous FULL: хостовая SQLite 3.50.4 входит в опубликованный диапазон ошибки WAL. WAL не включать без отдельной проверки исправленной версии. База — на локальном диске/локальном томе Docker, не на сетевом диске.

Индексы обслуживают временные ряды пациента, сообщения, готовые события и действующего ведущего врача; FTS5 индексирует записи и обновляется триггерами. Выборка ограничена 100 строками, возрастной фильтр/поиск параметризованы. Скорость, нагрузка и пределы числа пользователей не измерялись — T09/T11 требуют S15.

Новые версии шкал/лекарств/правил хранятся в catalog_versions со ссылкой на source_versions. Неактивное определение можно добавить данными; тест проверяет две версии без изменения схемы. Интерпретаторов/клинического ядра пока нет: полное T10 не заявлено. Новые функции выделяются в модули и регистрируются через фабрику приложения; при росте — отдельные Flask Blueprints. Изменение модели — следующая SQL-миграция; принятые миграции неизменяемы. Переезд на PostgreSQL потребует адаптера repository, миграции данных, замены FTS/SQLite-триггеров и проверки конкуренции; автоматической переносимости нет.

## Границы безопасности

Демо привязано к 127.0.0.1; Docker публикует порт только на loopback. Допустимые Host — localhost/127.0.0.1/[::1]. UI не имеет изменяющих методов, форма поиска только GET. В базе пациенты/документы ограничены synthetic=1; seed принимает только неактивные синтетические случаи. Никаких внешних запросов приложения, телеметрии, облачного ИИ/почты/SaaS нет.

Назначения/направления/изменения плана в UI отсутствуют. В модели care_actions требует approved-подтверждение, подтверждение — текущего ведущего врача и точную версию проекта. Подтверждение и подтверждённый проект нельзя переписать. Это дополнительные ограничения базы, не готовая серверная авторизация: аутентификация, проверка каждой операции и изоляция двух кабинетов остаются S05/S14. Файл БД у владельца машины не является защищённым клиническим хранилищем. Реальные данные, медицинский запуск, публичный доступ и соответствие законодательству не проверены/не разрешены этой приёмкой.

В аудит не пишутся пароли/токены/полные медицинские тексты; ошибка worker сохраняет только класс исключения. append-only защищён триггерами от обычного UPDATE/DELETE, но не от администратора SQLite. Резервирование/восстановление и сбои питания проверяются отдельно S15; обычный перезапуск процесса не заменяет эти испытания.
