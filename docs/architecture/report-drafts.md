# S27: личный черновик самоотчёта

21.10.2026. Только локальный синтетический прототип. Реальный медицинский/правовой допуск не изменён.

Один текущий черновик на владельца-пациента и его карточку хранится в SQLite, отдельно от клинических источников. Сервер восстанавливает поля при открытии кабинета. Сохраняются исходные строки, пробелы, незавершённые поля и противоречия, дата наблюдения и прежний request_key. Медицинская проверка выполняется только при явной отправке. Черновик не участвует в расчётах возраста/риска, поиске врача, динамике, сводке, уведомлениях или критических событиях.

`014_report_drafts.sql` добавляет только self_report_drafts: владелец/пациент, revision, версия бланка 1, active, ключ отправки, JSON полей, UTC-время. Старые миграции неизменны. INSERT/UPDATE дополнительно проверяют владельца/роль/неотключённый аккаунт/синтетическую карточку в SQL. Поля сохраняются по ограниченному списку и прежним размерам; незавершённость не блокируется клинической валидацией. Сеансовые токены, CSRF, пароль и UI-поля не сохраняются в JSON. Файл БД использует прежние права 0600.

GET/POST `/patients/<id>/self-report-draft` доступны только владельцу-пациенту. Врач получает 403, другой пациент 404, без входа — переход ко входу; POST требует прежний CSRF. GET возвращает только свой черновик; ответы no-store. POST save/delete поддерживает JSON-квитанцию и обычный бланк с redirect 303. Сохранение требует base revision; конфликт вкладок не перезаписывает текущий текст. Повтор идентичного сохранения после потерянного ответа возвращает текущую квитанцию. Неизвестные поля не сохраняются; значения экранируются при показе.

Автосохранение — через 600 мс после ввода, один запрос за раз. При неизвестном результате повторяется прежний снимок и ключ, затем сохраняется более новый ввод. При переходе страницы в фон несохранённый ввод отправляется с keepalive; это дополнительная попытка, а не гарантия. Перед закрытием нужно дождаться подтверждённого статуса. При отсутствии связи/сбое остаётся предупреждение об уходе; последняя неподтверждённая правка может потеряться. Автоматическая отправка врачу отсутствует. Пустой нетронутый бланк не сохраняется при закрытии/перезагрузке.

Без JavaScript доступны отдельные кнопки сохранения/удаления; сохранение незавершённого бланка не требует заполненной даты. Данные можно восстановить после перезагрузки, закрытия вкладки, повторного входа и перезапуска сервера. В localStorage/sessionStorage медицинского текста нет.

Перед явной отправкой JS дожидается сохранения актуального черновика и приостанавливает автосохранение. records.save проверяет revision внутри своей транзакции; успешная запись и очистка соответствующего черновика атомарны. Уже существующая квитанция проверяется первой, поэтому повтор не создаёт ещё один самоотчёт. Ошибка записи откатывает и клинические изменения, и очистку черновика. Старые интеграции без draft_revision сохраняют контракт; чужой активный черновик другим ключом не удаляется.

После отправки/удаления остаётся номер версии и ключ без текста (`active=0`, JSON `{}`). Старый autosave не может вернуть прежний текст: версия уже изменилась, отправленный ключ дополнительно отвергается. Новый бланк получает новый ключ с текущей версией. При конфликте вкладок несохранённые правки остаются в той вкладке; ссылка открывает сохранённый вариант отдельно, без автоматической перезаписи.

Текущий текст хранится до удаления или отправки. Очистка относится к рабочей таблице; резервные копии содержат снимок всех таблиц и управляются прежним локальным порядком backup/restore. Защита от владельца машины и удаление прежних копий не заявлены.

Проверки: apps/tests/test_report_drafts.py и evidence/S27. Реальных пациентов, устройств и скринридера в этих проверках нет.
