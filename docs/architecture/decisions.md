# Решения по стеку S04 — 18.10.2026

## ADR-001: минимальный локальный стек

Python 3.13.11, Flask 3.1.3, Waitress 3.0.2, sqlite3 стандартной библиотеки, Jinja/HTML/CSS. Все прямые/транзитивные runtime-зависимости зафиксированы в apps/requirements.lock. Версии и лицензии установленных пакетов — evidence/S04/dependencies.json, точные тексты — evidence/S04/licenses/. Frontend build/Node/npm, облачный ИИ, платные сервисы и ключи API не требуются. Python на хосте уже есть, новые расходы 0 ₽. Первый setup/build требует загрузки общедоступных дистрибутивов; дальнейшая работа демо сети не требует.

Исследователь подтвердил поддержку Python 3.13 и документацию; отчёт с URL — evidence/S04/external-check.md. Контейнер python:3.13.11-slim закреплён реально полученным digest, не плавающим latest. Проверены ARM64 macOS-хост и Linux ARM64 контейнер; другие ОС/архитектуры не проверены. Python/SQLite внутри контейнера фиксируются фактической проверкой, не предполагаются равными macOS.

## ADR-002: SQLite с rollback journal

Для локального демо нужен файл базы и минимум обслуживания; PostgreSQL добавил бы сервис/зависимости до измеренной необходимости. FTS5 даёт поиск по записям, индексы — временные выборки. Ограничение — один писатель; горизонтальное масштабирование не заявлено. Рабочий поток и сервер имеют разные соединения и короткие транзакции.

Исследователь нашёл официальное сообщение SQLite о WAL race до 3.51.3 (backport 3.50.7); на хосте 3.50.4. Поэтому journal_mode=DELETE, synchronous=FULL. Решение проверяется healthz/test. Не обещаем исправление сторонней библиотеки настройкой: просто не используем затронутый режим. Переход к WAL/иной СУБД — отдельное проверенное изменение.

## ADR-003: схема прежде функций

Каркас содержит все сущности F01–F08/M01–M10, но не имитирует готовые кабинеты/медицинские функции. Клинические определения пусты, формы и тексты шкал не копируются. Seed импортирует только шесть синтетических профилей/заголовков S03; исходные файлы/holdout не меняются. Рекомендации из S03 не исполняются. Статусы unknown/conflicting сохраняются. Веб-слой только чтение; CLI seed — техническая подготовка.

## ADR-004: outbox в той же транзакции

Без брокера сообщений для этого масштаба: outbox + транзакционный обработчик + идемпотентная локальная квитанция. После перезапуска событие доступно worker. Обработка ошибки откатывает частичные записи, сохраняет только класс ошибки, ограничивает повторы. Неизвестные темы уходят в dead; удаление/сброс ошибок не автоматизирован. Таблица deliveries предусмотрена для S10/S11, сейчас не используется. Реальные отправки и задержки доставки не заявлены.

## ADR-005: права и конфиденциальность

Пакеты BSD-3-Clause (Flask/Werkzeug/Jinja2/MarkupSafe/ItsDangerous/Click), MIT (Blinker), ZPL-2.1 (Waitress); лицензии сохранены с точными дистрибутивами. Python — PSF-2.0, SQLite — public domain по отчёту исследователя. Это инвентаризация компонентов, не юридическое заключение о всём продукте/отчуждении. Базовый образ содержит системные пакеты; полный SBOM/их уведомления проверить перед внешней передачей S14/S17/S22. Внешние правила конкурса о Codex/open source всё ещё B06, отсутствие ответа не превращено в разрешение. Разработка каркаса выполняется в уже порученном объёме, материалы/данные новым внешним сервисам не передавались. B03/B04 и реальные согласия/права команды остаются отдельными проверками.

## ADR-004 — доступ S05, 18.10.2026

Непрозрачная случайная cookie, хэш SID/состояние на сервере, CSRF и постоянные лимиты в SQLite; новые пакеты/внешний провайдер не нужны. Роль из users, доступ врача через текущую care_relationships в каждом запросе. Приглашение привязано к отдельному получателю, а не только к изменяемому владельцу карточки; активация связи и потребление атомарны. Технический отчёт пары подтверждает маршрут S05 без активации форм/клинической записи. Полные условия/пределы — access.md; независимое исследование — evidence/S05/external-check.md. Режим остаётся локальным синтетическим, не готовым внешним клиническим хранилищем.
