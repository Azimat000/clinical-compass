# Извлечение literal-v1 — S12

Локальный детерминированный разбор регулярными выражениями, без модели/API/новых зависимостей. Принимает вставленный текст или один .txt UTF-8/UTF-8 BOM до 24 000 байт. Общий HTTP-запрос ограничен 65 536 байт; превышение — 413 с пояснением. Другие кодировки/управляющие символы/пустой ввод/неподдерживаемые расширения отклоняются. Файл используется как текст, имя не сохраняется, на диск файл не исполняется. PDF/DOCX/OCR/таблицы/архивы не поддержаны; конкурсных подтверждений обязательных форматов нет (C42/B09).

## Зафиксировано до holdout

Поддерживаемые поля — FIELDS в apps/compass/extraction.py: возраст, дата, упоминание диагноза, препарат, доза с единицей, кратность, аллергия, беременность, вскармливание, небольшой словарь симптомов, фраза о самоповреждении. Сопутствующие препараты/дата начала выделены в перечне проверки, но отдельного надёжного правила их извлечения нет. Нераспознанные поля явно перечисляются; список не является клинически исчерпывающим. Отсутствие кандидата не становится false/нулём. Единицы не пересчитываются, диагноз не выводится из симптомов. Нет поддержки произвольных торговых названий/сокращений/синонимов. Даты числовые и русские названия месяцев; недействительная календарная дата остаётся invalid. Привязка даты к событию/приёму/получению не реализована: даты — кандидаты event_date, контекст проверяет врач. Два разных возраста/дозы сохраняются как конфликт. Историчность/отрицание/неизвестность определяются ограниченными словами в предложении, возможны ошибки области действия и времени. Не реализован полноценный разбор цитат/чужой речи; фразы самоповреждения всегда unknown, не запускают/не подавляют критический сигнал.

Набор development: 24 профиля S03-v1, разрешён для разработки. Holdout: 12 других профилей, выделен до реализации S12, файлы не меняются. Автор набора Codex видел его при S03: ограниченная независимость, не слепая внешняя оценка. Freeze фиксирует SHA-256 программы/оценщика/разметки до первого запуска holdout. После просмотра результатов алгоритм не подстраивается. При изменении алгоритма оценка этого набора становится повторной; для новой независимой оценки нужен новый набор.

Единица совпадения: поле + статус утверждения + нормализованное значение + пересечение точной исходной цитаты с размеченным фрагментом. Одно предсказание совпадает максимум с одним эталоном. Не совпавший статус — FP и FN, даже при верном значении. Кандидаты вне target_fields конкретной записи исключаются из численной оценки; все размеченные целевые поля, включая неподдерживаемые, входят в FN. Precision = TP/(TP+FP), recall = TP/(TP+FN), нулевой знаменатель = null. Метрики по всем утверждениям (micro), по полям/шаблонам; development и holdout раздельно. Точное совпадение цитаты со строкой проверяется для каждого кандидата, не только совпавшего.

Все FP/FN сохраняются, без выборки удачных случаев. Отдельно: нулевое распознавание, риск-поля (возраст, препарат, доза/кратность, аллергия, беременность/лактация, самоповреждение/чужая/историческая речь, дыхание), поля critical_missing_fields S03 и ошибочное утверждение известного значения для них. Эти категории технические, не врачебная оценка клинической тяжести. Нет заранее заданного конкурсного численного порога; результат не объявляется клинически достаточным по произвольному проценту.

## Врачебная сверка и хранение

Только действующий связанный врач может импортировать и добавлять сверки. Пациенту этот раздел закрыт. Полный исходник/хеш, версия кандидатов, автор, связь, время и точные координаты цитат сохраняются неизменно. При подтверждении сервер требует исходные значение JSON, статус и цитату. Исправление/отклонение/добавление требуют причины и точной цитаты из исходника; не подтверждают медицинскую истинность и не исключают ошибку врача. Каждая сверка отдельна, предыдущая остаётся видимой; повтор того же ключа не дублирует, другое содержимое409. Проверки доступа/сохранение/audit атомарны. Тексты не включаются в audit metadata.

Сверки не меняют возраст, observation, clinical_context, назначения или направления. Не являются утверждённым полным клиническим резюме. Перенос в действующие процессы выполняет врач отдельно через существующие формы/подтверждение. Новые импорты/сверки меняют снимок исходных данных неподтверждённого проекта решения и требуют его пересмотра; прежние пустые снимки совместимы, подтверждённые решения не переписываются. Исходник можно просмотреть целиком. История не содержит реальных ПД: только синтетика; работа с реальными файлами/клинический запуск не разрешены этой проверкой.

Запуск: `.venv/bin/python evidence/S12/evaluate.py development holdout`. Результат — stdout JSON; команда не меняет программу/набор. При повторном запуске после раскрытия эталонов результат называется проверкой воспроизводимости, не новой независимой оценкой.
