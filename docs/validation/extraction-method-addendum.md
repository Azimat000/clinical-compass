# Поправка к оценке S12

При финальной ручной проверке найден дефект оценщика: сериализация JSON различала 10 и10.0. Разметка содержит целые дозы, программа возвращает числовые значения float. Это одинаковые числа, прежний способ сравнения создавал лишние FP/FN. Никакого изменения извлечения/настроек/словарей по holdout не делалось.

Замороженные extraction.py, evaluate.py, extraction-method.md, оба набора сохранены побайтно (freeze.json). Первый отчёт сохранён как extraction-results-initial.json. Исправленный оценщик — evaluate_corrected.py, единственное изменение сопоставления: сравнение числовых значений/вложенных объектов непосредственно, вместо сравнения строки JSON. Поле/статус/пересечение цитаты/один-к-одному остаются прежними. evaluate.py и команда в замороженном исходном методе воспроизводят исторический ошибочный результат; для действующей оценки:

`.venv/bin/python evidence/S12/evaluate_corrected.py development holdout`

Действующий extraction-results.json: development92TP/17FP/49FN,precision84,40%,recall65,25%;holdout31TP/12FP/38FN,precision72,09%,recall44,93%,20FNриск-полей. Это пересчёт измерения известного набора после исправления оценщика, не новая независимая оценка и не настройка extractor. Не исключены неподдерживаемые целевые поля/неудобные примеры. Алгоритм неизменен, малый синтетический набор/ограниченная независимость/необходимость клинической и внешней проверки сохраняются.

Уточнение ссылок замороженного метода: отсутствие конкурсного формата относится кB07/C42, неB09. Дополнительная веб-граница (после фиксации алгоритма): не более100цифр подряд; большие числа отклоняются до вызова извлечения, не влияют на результатыS03. См. test_extraction и итоговые логи.
