# Локальный запуск «Клинического компаса»

Каркас S04, кабинеты S05, карточка/самоотчёты S06 и измерение симптомов S07, 19.10.2026. Только синтетическое демонстрационное окружение. Запускайте команды из папки HAC. Проверены Python 3.13.11/macOS ARM64 и Docker/Linux ARM64. Для интерфейса не нужны ИИ-сервисы, внешние API или платные подписки. Вход — локальная демонстрационная учётная запись.

## Обычный запуск

Нужны Python 3.13 с venv/SQLite FTS5 и make. Создание нового окружения скачивает восемь пакетов из PyPI; запускаемый продукт к PyPI не обращается.

```sh
make setup
make migrate
make seed
umask 077
.venv/bin/python -m apps.compass seed-accounts > var/demo-credentials.json
make run
```

Открыть http://127.0.0.1:8000. Логины и случайные пароли — в локальном var/demo-credentials.json (не в Git). seed-accounts печатает только новые пароли, не сбрасывает существующие: повторный запуск возвращает пустой список. Не перезаписывайте единственную нужную копию паролей повторной командой. Это явная локальная операция, HTTP-регистрации/выбора роли нет. Обычный seed-demo не включает учётные записи автоматически.

Врач doctor-demo создаёт приглашение по D01; пациент patient-D01 принимает его в своём кабинете. До принятия врач не видит карточку. Пациент нажимает «Отправить проверку связи»; врач открывает карточку и видит тот же технический отчёт. Для проверки другого врача есть doctor-other, другие пациенты patient-D02–D06. Личные сведения не вводить. В S06 пациент заполняет «Самоотчёт»: дата наблюдения, субъективное самочувствие, возраст/дата рождения по известности, отдельные жалобы/риски/препараты/НЯ и необязательное резюме. Нажатие «Отправить самоотчёт» сохраняет запись; врач открывает ту же карточку и видит её без пересылки. Врач добавляет визит своей формой, пациент видит его в истории. Ссылка «Посмотреть динамику» ведёт к таблице дат и источников. Статусы «неизвестно», «явно отрицает», «противоречивые сведения» различаются. НЯ сохраняются отдельно с происхождением, без утверждения причинности. DASS-42 предлагается ведущим врачом: сверенный возраст и источник → «Предложить DASS-42» → пациент открывает анкету → отправляет вымышленные ответы → врач видит три суммы/исходные ответы/историю, пациент — только квитанцию. Дневник пациента и график субъективного самочувствия доступны отдельно. Назначения пока не реализованы. Исправление — новая запись; прежние не удаляются.

В отдельном терминале из HAC:

```sh
make worker
```

Остановка каждого процесса — Ctrl+C. Повторить make run/make worker: база var/compass.sqlite3 и события сохраняются. Повтор make seed не дублирует случаи. База и .venv игнорируются Git, исходный синтетический набор не меняется. Без seed/seed-accounts входных учётных записей нет; кабинет врача до приглашений показывает пустую выборку.

Для отдельной базы/порта:

```sh
.venv/bin/python -m apps.compass --db var/alternate.sqlite3 seed-demo
.venv/bin/python -m apps.compass --db var/alternate.sqlite3 serve --port 8001
.venv/bin/python -m apps.compass --db var/alternate.sqlite3 worker --once
.venv/bin/python -m apps.compass --db var/alternate.sqlite3 status
```

worker --once обрабатывает все уже доступные события и завершается; события с отложенным повтором ждут следующего запуска. Обычный worker ждёт их постоянно. Технические квитанции S04 не являются уведомлениями врача.

## Контейнер на чистом окружении

Нужны Docker и Compose. Python и пакеты устанавливаются в закреплённом образе, не зависят от .venv хоста:

```sh
docker compose up --build -d --wait
docker compose ps
docker compose exec -T web python -m apps.compass status
umask 077
mkdir -p var
docker compose exec -T web python -m apps.compass seed-accounts > var/docker-demo-credentials.json
docker compose exec -T web python -m unittest discover -s apps/tests -v
docker compose restart
docker compose ps
docker compose down
```

Порт — 127.0.0.1:8000; изменить при занятости: COMPASS_PORT=8001 docker compose up --build -d --wait. web автоматически мигрирует/заполняет только синтетику; worker запускается после healthcheck. Том compass-data хранит базу после restart/down/up. down без -v сохраняет том. Не использовать down -v для нужных данных: это удаление. При проверке S04 использован отдельный проект hac-s04/порт 18004 и новый пустой том.

## Реальные проверки

```sh
make check
python3 tools/validate_plan.py
python3 tools/session.py status
git diff --check
```

make test: самоотчёт/визит/история/источники НЯ/возраст и противоречия/повтор запроса/откат всей записи/обновление базы S05→S06/безопасный вывод текста, вход/CSRF/роли/прямой чужой доступ/истечение и отзыв сессий/приглашения/отчёт пары, ограничения модели, миграции/откат/хеши, unknown/conflicting, запрет балла неполной анкеты, подтверждение врача, поиск/индекс, устойчивые повторы/очередь ошибок, экранирование/Host; HTTP-клинические действия закрыты.

make smoke: временная пустая база, наполнение, два настоящих запуска Waitress с остановкой процесса между ними, настоящий вход двух ролей/приглашение/общий технический отчёт + самоотчёт/визит/НЯ/повтор без дубля/запрет чужого доступа после обоих запусков, затем отдельный worker и проверка 6 сохранённых случаев/6 обработанных событий/6 квитанций/integrity_check. Временные данные очищаются автоматически, рабочая база не затрагивается.

make check дополнительно запускает pip check и существующие тесты плана/синтетики. validate_plan отдельно: после изменения статуса accepted, до создания нового тега нужен --pending-tag S07, после тега — без него. Зелёные тесты каркаса не подтверждают медицинскую применимость/безопасность или готовность конкурса.

## Неисправности и следующие срезы

- Ошибка FTS5 при миграции: эта сборка SQLite не подходит; использовать проверенный контейнер. Не заменять молча поиск другой реализацией.
- Migration checksum mismatch: восстановить исходный принятый SQL из Git, затем отдельная новая миграция; не править schema_migrations вручную и не удалять рабочую БД.
- Database is locked: остановить лишние писатели, проверить локальный диск; timeout 10 секунд, рост нагрузки исследовать S15. Не включать WAL на затронутой версии.
- События dead: проверить тему/код/last_error без копирования содержимого; после исправления отдельная управляемая повторная обработка. Веб-интерфейса управления очередью пока нет.
- Изменение профиля в исходном наборе не перезаписывает импортированный seed. Для экспериментальной синтетики использовать новую --db; не применять это к реальным данным.

S05 реализован для локального синтетического демо. Сессия: 8 часов абсолютный срок, 30 минут без запросов; logout отзывает на сервере, повторный вход меняет SID. Cookie HttpOnly/SameSite=Strict; в БД только хэш SID. CSRF обязателен для POST, включая выход; вход использует отдельный одноразовый challenge на 10 минут. Лимит 10 попыток за 15 минут по аккаунту и адресу (успешные попытки тоже считаются); за обратным прокси адрес клиента/доверие отдельно не настроены. Приглашение 24 часа, однократно, фиксирует получателя; чужой код, отзыв, истечение, отключённый врач не дают связь. Другие приглашения этого пациента аннулируются, смена ведущего врача через HTTP недоступна. Отчёт проверки связи технический; S06 добавляет отдельный самоотчёт и визиты. Правила хранения/дат/противоречий — docs/architecture/records.md. После приёма запись видна при открытии/обновлении страницы, автоматические уведомления ещё S10.

По умолчанию HTTP строго на loopback машины (Compose также публикует только 127.0.0.1). При подготовке HTTPS есть COMPASS_COOKIE_SECURE=1 (Secure/HSTS), однако это само по себе не разрешение публикации: TLS, прокси, усиление scrypt, аудит/жизненный цикл аккаунтов/смена паролей/мониторинг/резервное копирование ещё не приняты. Не выкладывайте credentials/базу/токены в доказательства или презентацию. Нет HTTP-смены ролей/паролей; административные изменения в БД потребуют отдельной процедуры с отзывом всех сессий. Документы доступны только как список метаданных; выдача файлов не включена, произвольный storage_key не читается. API действий возвращает отказ и не создаёт клинических записей. До этого ни реальных пациентов, ни публичного сервера. B03/B04 снимаются перед медицинскими алгоритмами. S10/S11 проверяют доставку; S14/S15 — безопасность/нагрузку/резервное восстановление. Схема сама по себе не исполняет эти функции.

## S07: анкета и динамика

Новых пакетов или настроек не нужно. create_app применяет 004_assessments и устанавливает проверенный источник/точную форму для synthetic_demo, не меняя старые миграции/ответы. Старые контейнеры требуют пересборки стандартной командой выше; прежний том/пароли сохраняются. Перед обновлением нужных данных сохранить SQLite backup по проверенной процедуре, не удалять том.

Врач открывает связанную карточку, вводит сверенный возраст на сегодня и источник; кнопка «Предложить DASS-42». Для исходного D01 в чистом наборе возраст 35. Вымышленный источник указывается честно. Неизвестный возраст не позволяет молча выбрать 18; противоречия сначала сверяются. Предложение действует сегодня, не более 24 часов. Пациент видит ссылку, выбирает ответы точной формы и передаёт врачу. Врач может ввести ответы сам с сохранением своего авторства.

Полная анкета даёт врачу три отдельные суммы 0–42 без общего балла/порогов/интерпретации. При любом пропуске ни одна сумма не считается; ответы сохраняются. Пациент после отправки видит квитанцию/дату/версию, без DASS-ответов/сумм. Это касается и API. В дневнике пациент видит собственные записи и график категорий лучше/без изменений/хуже/не указано; это отдельное субъективное описание, не медицинская шкала. Врач видит те же самоотчёты и отдельную динамику DASS одной версии.

Проверки S07 включены в make check: ручные векторы, пропуски во всех 42 позициях, возраст/права/версия/CSRF/повтор/откат/история/смена связи, сохранность полной и неполной анкет после двух настоящих перезапусков. Правила хранения/источников — docs/architecture/assessments.md, применимости/прав — docs/clinical/scales-rights.md. Для источника/текста нужна новая версия, не UPDATE опубликованного JSON/каталога.

S07 не включает клинические решения/пороги/срочность из DASS. Пункт 21 отображается врачу как исходный ответ; экстренный алерт не заявляется до S09/S10. Для реального использования нужны отдельные проверки назначения/правового режима/апробации.

## S08A: решения врача на синтетике

В карточке откройте «Решения врача». Связанный врач может вручную сохранить проект пяти видов решений, затем отдельно подтвердить или отклонить его. Пациент видит только подтверждённые записи. На момент подтверждения данные/план/источники/день должны совпадать с проектом; при409 просмотрите сведения и создайте новую редакцию. Дозы и лекарственные курсы автоматически не назначаются, клинические правила не активированы. Старый общий API записи actions закрыт. Подробности — docs/architecture/clinical-decisions.md. Прежние команды запуска/миграций сохраняются; добавлена005_decisions, старые SQL не изменены. Рабочие тома вручную не сбрасывать.

## Уточнение возраста — S08B

При расхождении возраста откройте в карточке «Сверка возраста врачом», просмотрите перечисленные источники, укажите вымышленную сверенную дату рождения и основание, подтвердите просмотр и сохраните. Обычный визит не снимает прежние противоречия автоматически. История остаётся доступной. После новых сведений потребуется повторная сверка; прежнее предложение DASS нужно заменить новым. Предложения до обновления S08B без токена проверки тоже нужно создать заново, завершённые результаты сохраняются. Возраст 18–120 — политика DASS в демо; из неё не следует применимость лекарства. Подробности: docs/architecture/age-reviews.md.

## S08: справка и оценка терапии

Откройте «Решения врача»: доступны варианты терапии и подробная справка Авиандра. Для назначения, изменения и отмены дополнительно заполните восемь областей оценки и результат рассмотрения препарата. В каждой области нужны состояние и пояснение; неизвестность — допустимый честный результат, но не завершённая сверка. Отказ от выбора препарата/недостаток данных также сохраняются. Отдельное подтверждение врача требуется после сохранения проекта. В демо заполняйте вымышленные сведения.

Новая справка v2 делает прежние неподтверждённые проекты устаревшими: создайте новую редакцию после просмотра источников/данных. Подтверждённая история и старая справка v1 сохраняются. Новых зависимостей/миграций нет, штатная пересборка/перезапуск прежние, сбрасывать базу не нужно. Автоподбор, автоматическая совместимость/дозы/критичность НЯ не включены. Подробности и границы — docs/architecture/therapy-review.md.
