## Продуктовое решение

Локальное веб-приложение двух кабинетов. Основной объект — одна непрерывная история пациента, связанная с ведущим врачом: исходные сведения → самоотчёт → проверенная оценка → рассмотрение врачом → подтверждённый план → наблюдение/коммуникация. Одна и та же запись доступна обеим ролям в положенном объёме, без ручной пересылки.

Шкала DASS-42 Фаттахова–Горобец собирается только в закрытой связанной паре. Врач получает исходные ответы, три отдельные суммы, источник/версию и сопоставимую историю. Пациент получает квитанцию и отдельно видит дневник своего самочувствия/жалоб/НЯ. Баллы не диагноз; назначения/маршруты/изменения плана не следуют из них автоматически. Это сохраняет F01/F04/F05/M08 и соблюдает режим выбранной формы.

PHQ-9/GAD-7 поимённо конкурсом не предписаны. Показ численных баллов пациенту тоже не предписан. Поэтому отсутствие научной связи конкретного PHQ-перевода не должно останавливать внедрение другого подтверждённого инструмента. Политика 18+ применяется только к этому демонстрационному инструменту, не подменяет аудиторию всего конкурса.

## Десять обязательных условий

M01/M02: общий серверный контроль роли/связи и прямой приём записей. M03: пять видов клинического действия требуют врача, контроль действует и при прямом запросе. M04: каждый основной демонстрационный случай содержит профиль, рассмотрение Авиандра, рекомендации по лечению и маршрут; «рассмотреть» не значит назначить всем. M05: научно обоснованные критические признаки и реальный экстренный сигнал/повтор/реакция врача; технический event-worker не считается алертом. M06: текст/значки/категории, а не один цвет. M07: РФ-регистрация/актуальные показания/противопоказания/дозы; вне инструкции не предлагается системой автоматически. M08: версия/источник/точная валидированная форма/права для каждого активного элемента. M09/M10: правовой режим и конфиденциальность проверяются по фактическому использованию, не по наличию таблицы consents.

Точный листок-вкладыш ГРЛС не переименовывается в ОХЛП и не заменяется копией производителя. B04 экспертных клинических правил остаётся перед их включением. Демонстрационный врач не обозначается реальным внешним проверяющим.

## Пять сквозных демонстрационных линий

1. Исходное ведение: профиль → оценка → обоснованная справка → подтверждение врачом → доступный пациенту план.
2. Критические сведения: приём → доказанное правило → заметный алерт → доставка/повтор → реакция врача → подтверждённый маршрут.
3. НЯ/неизвестность/противоречие: сохранить источник → не сделать опасный вывод → врач уточняет данные.
4. Повторное наблюдение: новый самоотчёт → пациентская динамика → повторная сопоставимая оценка врачу → история решений без стирания.
5. Приверженность и связь: назначенный врачом план → выполнение/пропуск/нет ответа → сообщение в обе стороны → сохранность после разрыва.

Линии используют существующие 6 синтетических случаев, не заменяют их менее полным набором. Клинические эталоны до реального утверждения остаются проектами. Во всех основных случаях сохраняется M04; каждый F-ID имеет самостоятельное доказательство, не только один эффектный экран.

## Апробация и организация до защиты

Сейчас B04/B05: реальный клинический проверяющий и критерий апробации не подтверждены. Рациональный формат прототипа — настоящие специалисты/пользователи выполняют задания на синтетических случаях с протоколом результатов/ошибок/ограничений. Не называть это исследованием клинической эффективности на пациентах. Кейс не предписывает реальные пациентские данные; принятый организатором формат уточняется по установленному каналу. Контакты/согласия/реальный вклад не выдумываются и не публикуются в Git.

Сроки открытых источников: 28.10 онлайн-предзащита, 30.10 финал/постеры. К 26–27.10 нужен фактический пакет доказательств, запуск без интернета, резервная запись/инструкция, постер и репетиция. Это наши внутренние даты, а не подтверждённый дедлайн загрузки. Точное время, питч/Q&A, форматы/канал загрузки/постера, веса/приоритет и правила ИИ берутся из чата; он недоступен агенту. Gmail требует восстановления через /mcp/настройки. Все вопросы/владельцы сохранены в docs/contest/questions.md, внешние ответы — memory/EXTERNAL.md.

Команда 2–5, оба профиля, не больше двух технических; пользователь подтвердил 5 участников, индивидуальные документы не проверены. Собственное авторство, зависимости и сторонние формы перечисляются честно. Public domain DASS не передаётся как исключительное собственное произведение команды; это не одностороннее изменение договора конкурса. Формальный правовой комплект/передача проверяются S17/S22, без самовольной отправки/подписи. Публичный финал не разрешает общий публичный репозиторий.

## Порядок и ресурсы

В этой сессии — только повторный аудит и S07. После приёмки — S08, затем остальные карточки по STATE/ROADMAP. Не растягивать внешние консультации до дня S16: доступные ответы/контакты проверять каждую сессию. Если конкретная клиническая активация заблокирована, перед независимой реализацией отдельно разделить карточки/зависимости с сохранением всего покрытия; не объявлять зависимый незавершённый этап принятым.

Продукт остаётся локальным, без внешнего ИИ/API и платных сервисов внутри приложения. Новый инструмент/графики используют прежние пакеты, стоимость разработки в денежном журнале не увеличивается. Лимит 5 000 ₽, потрачено/обязательства 0; печать/дорога оцениваются по фактическим условиям и не считаются оплаченными.

Демонстрационный прототип, внешняя апробация, полнота конкурсной заявки и медицинский запуск — разные результаты. Один успешный срез не означает выполнения всего конкурса. Postcontest/реальные медицинские действия/публикации/покупки не запускаются автоматически.
